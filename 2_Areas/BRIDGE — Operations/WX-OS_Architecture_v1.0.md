## 1. Tại Sao AI-First?

Workshop X có 26 người, 4 PX, 8 product lines, 1064+ units shipped. Coordination complexity đang vượt khả năng quản lý manual:

| Vấn đề | Manual | AI-First |
|--------|--------|----------|
| "Đủ vật tư cho WO mới không?" | CEO kiểm tra kho + nhẩm tính | AI cross-reference BOM × stock × all active WOs trong 2 giây |
| "PX nào đang overload?" | Hỏi 4 quản đốc | AI tính capacity từ WO data, hiển thị heatmap |
| "WO này có kịp deadline không?" | Kinh nghiệm ước lượng | AI tính routing time + queue delay + material availability |
| "Cần mua gì tuần này?" | NV kho báo thiếu khi đã hết | AI dự đoán trước dựa trên WO pipeline |

**Nguyên tắc cốt lõi:** CSV vẫn đọc được bằng Excel nếu không có AI (graceful degradation).

## 3. Năm Nguyên Tắc AI-First

| # | Nguyên tắc | Giải thích | Ví dụ |
|---|-----------|------------|-------|
| 1 | **Query, don't navigate** | CEO hỏi bằng ngôn ngữ tự nhiên, AI tìm across all data | "PX nào đang rảnh?" thay vì mở 4 file CSV |
| 2 | **Infer, don't just report** | AI tính toán, dự đoán, flag conflict — không chỉ hiển thị data | "WO-003 sẽ trễ 5 ngày vì WS-CKCX overload" |
| 3 | **Connect domains** | 1 query chain across WO → BOM → Stock → Cost → Schedule | Tạo WO → tự động check vật tư → flag thiếu → suggest PO |
| 4 | **Compound learning** | Mỗi WO completed = data point cho lead time optimization | Sau 5 WOs: "TOWED-TARGET thực tế 9.2d vs planned 7.5d" |
| 5 | **Graceful degradation** | CSV đọc được bằng Excel, markdown đọc được bằng Obsidian | Không phụ thuộc AI để truy cập data cơ bản |

## 4. Intelligence Algorithms

### 4a. Material Availability Check
```
Trigger: Tạo WO mới, hoặc xem WO dashboard
Input:   _bom_master.csv + _work_orders.csv + _stock_ledger.csv
Logic:   demand = Σ(wo_qty × bom_qty_per_unit) per item across ALL active WOs
         surplus = stock_on_hand - total_demand
Output:  ✅ ĐỦ | ⚠️ VỪA (surplus=0) | ❌ THIẾU [N] + which WOs affected
```

### 4b. PX Capacity Heatmap
```
Trigger: /ops hoặc /ops production
Input:   _work_orders.csv + _routing.md
Logic:   load = Σ(remaining_units × hours_per_step) per PX
         capacity = 4 workers × 8h = 32h/day
         utilization = load / capacity
Output:  🟢 <50% | 🟡 50-80% | 🔴 >80% per PX
```

### 4c. Delay Prediction
```
Trigger: /ops hoặc /ops production
Input:   _work_orders.csv + _routing.md + _stock_ledger.csv + _bom_master.csv
Logic:   predicted_end = start_date + routing_lead_time + queue_delay + material_delay
         queue_delay = if PX has multiple WOs, estimate wait
         material_delay = if ❌ THIẾU, add ~7 days procurement
Output:  ✅ On track | ⚠️ At risk (within 3 days) | 🔴 Late + reason + action
```

### 4d. Reorder Alert System
```
Trigger: /ops hoặc /ops inventory
Input:   _stock_ledger.csv + _bom_master.csv + _work_orders.csv
Logic:   net_available = stock_on_hand - Σ(production_demand_all_active_WOs)
         priority = by production impact (blocking WOs first)
Output:  🔴 BLOCKING (net<0, WO target <30d) | 🟡 LOW (below reorder) | ✅ OK
```

### 4e. Compound Learning
```
Trigger: After ≥5 completed WOs for same product
Input:   _work_orders.csv (completed) + _daily_log.csv
Logic:   actual_avg_lead_time vs routing_estimate
         if deviation > 20% → suggest routing update
Output:  "TOWED-TARGET actual 9.2d vs planned 7.5d → update routing?"
```

| CRM | ⚪ Headers only | — | — |

### Phase 2: Finance + CRM (target: 2026-05)

- Finance intelligence: monthly P&L auto-generate, cost per WO, margin by product line
- CRM: customer pipeline linked to WOs, revenue forecast
- Trigger: CEO has validated Phase 1 data accuracy + daily logging habit established

### Phase 3: Staff Data Entry (target: 2026-06)

- QĐ nhập WO updates (Google Sheets → CSV sync hoặc Zalo capture)
- NV kho nhập stock adjustments
- KTT nhập invoices
- Trigger: Phase 2 stable + staff training complete

### Phase 4: ERPNext + OpenClaw (target: 2026-Q3)

**ERPNext (System of Record):**
- Migrate validated CSV data → ERPNext
- Minimal first: BOM + Work Order + Quality Inspection ONLY
- KHÔNG làm accounting/HR/CRM cùng lúc — avoid implementation trap

**OpenClaw (AI Agent Runtime):**
- Kết nối ERPNext qua API
- Giao diện Telegram cho team — không cần mở ERP
- 3 skills ban đầu: query WIP status, log gate results, buffer alerts
- Team nhắn tin bình thường, AI agent dịch intent → ERP query

### Phase 5: Multi-Agent + Security (target: 2026-Q4+)

**Paperclip (Multi-Agent Orchestration):**
- Khi cần 4+ agents chuyên biệt (Design QC, Procurement, Financial, Test Scheduler)
- Heartbeat protocol — agents biết về nhau, không conflict
- Budget caps + audit log — chống Paperclip Maximizer risk

**NemoClaw (Security Sandbox):**
- Zero-Trust: agent bắt đầu với zero permissions
- Chạy model cục bộ — data quốc phòng không lên cloud
- Khi scale 20+ người hoặc partner access

```
Full Stack Vision:
Tầng 4: Paperclip (orchestration)     ← Phase 5 (Q4+)
Tầng 3: NemoClaw (security sandbox)   ← Phase 5
Tầng 2: OpenClaw (AI agent, Zalo)     ← Phase 4 (Q3)
Tầng 1: ERPNext (system of record)    ← Phase 4 (Q3)
Tầng 0: WX-OS CSV + Claude Code       ← NOW (Phase 1-3)
```

## 9. Nguyên Tắc Thiết Kế Hệ Thống

1. **Validate process BEFORE committing to tool** — CSV + Claude Code trước, ERPNext sau
2. **One source of truth** — mỗi data point chỉ có 1 nơi lưu trữ
3. **CEO-first** — system phải hữu ích cho CEO trước, staff sau
4. **Incremental data** — bắt đầu với data CEO biết, mở rộng dần
5. **No silent failures** — nếu data thiếu/mâu thuẫn → AI phải flag, không giả định

## 11. Guard Rails — Chống Shifting the Burden to AI

| Rule | Lý do | Enforcement |
|------|-------|-------------|
| AI recommend, human decide | Team ngừng tự suy nghĩ | Mọi gate PASS cần human sign-off |

| Data quốc phòng không lên cloud | Air-gap requirement | Local-first architecture, NemoClaw khi scale |

## 12. ERP Leapfrog Gate — Evaluation Criteria (R4)

**Decision date:** 2026-07-15 (after 3 months WX-OS CSV operation)

**GO for ERP Leapfrog (stay CSV + AI):**
- [ ] CEO dùng `/ops` ≥ 4x/tuần consistently for 3 months
- [ ] `/ops production log` cuối ngày ≥ 80% working days
- [ ] Data quality: no conflicting data across CSVs detected in 3 months
- [ ] Compound learning: ≥ 1 routing update suggested from actual data
- [ ] QC: ≥ 20 QC records logged, FPY trackable per product
- [ ] No data lost or corrupted (git history = audit trail)
- [ ] Team (QĐ, NV kho) can provide input to CEO without ERP

**NO-GO — Need ERPNext:**
- [ ] CSV data conflicts recurring (2+ incidents/month)
- [ ] Multi-user edit conflicts (2+ people need to update same file)
- [ ] Accounting integration required (KTT needs linked invoices ↔ WOs)
- [ ] Customer/auditor requires formal ERP audit trail
- [ ] CEO spending > 30 min/day on data entry (tool should free time, not consume it)

**If GO:** Continue CSV + AI, evaluate again at 6 months.
**If NO-GO:** ERPNext minimal deployment (BOM + WO + QC only), migrate validated CSV data.

## 13. Air-Gap Architecture Requirements (R5)

**Current state (Phase 0):** ✅ SECURE by default
- All data in local git repo (d:\Workshop_X\)
- Claude Code runs locally, API calls to Anthropic only (no WX data stored)
- CSV files = plain text, no cloud dependency
- No external service has access to production/inventory data

**Phase 4 (ERPNext + OpenClaw) requirements:**
| Requirement | Implementation |
|-------------|---------------|
| ERPNext deployment | Local server in workshop, NOT cloud hosted |
| OpenClaw runtime | Self-hosted on local Linux machine |
| LLM inference | Local model (Qwen/DeepSeek) OR API with data minimization |
| Telegram interface | VPN nội bộ only, no internet-facing endpoints |
| Data classification | BOM/design = RESTRICTED, WO status = INTERNAL, stock levels = INTERNAL |
| Backup | Encrypted local backup + offline USB, NO cloud backup |
| Audit trail | Git log for CSV, ERPNext audit log for Phase 4 |

**Phase 5 (NemoClaw) requirements:**
| Requirement | Implementation |
|-------------|---------------|
| Zero-Trust agent | Agent starts with zero permissions, explicit approval per action |
| On-premise AI | NVIDIA inference on local hardware, no cloud LLM |
| Data gate | Agent CANNOT export BOM/design files outside network |
| Action logging | Every agent action logged with timestamp + approval chain |

**Red lines (NEVER cross):**
- ❌ Production BOM trên cloud server
- ❌ Design files accessible via internet
- ❌ Agent có quyền write không qua CEO approval
- ❌ Customer/order data trên third-party SaaS
