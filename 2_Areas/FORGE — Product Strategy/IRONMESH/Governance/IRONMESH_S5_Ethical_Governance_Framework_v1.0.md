# Defense AI Ethical Governance Framework — Workshop X

> **Purpose:** Formal governance framework for all AI-assisted defense products developed by Workshop X. Defines accountability, ethical boundaries, HITL architecture, data sovereignty, and compliance obligations.
>
> **Why this exists:** Vietnamese military procurement requires demonstrable governance over AI-assisted systems. "We use AI carefully" is not a governance framework — this document makes the rules explicit, auditable, and enforceable.
>
> **Scope:** All products where AI influences any output consumed by a military operator, including: target detection/classification, scoring/assessment, training analytics, system recommendations, and design/engineering outputs.

---

## 1. Governance Principles

### P1 — Human Authority Is Non-Negotiable

AI systems **inform, assist, and recommend**. Humans **decide, authorize, and act**. No AI system produced by Workshop X shall autonomously initiate any action with lethal, destructive, or irreversible consequences.

### P2 — Consequence Determines Automation Level

The automation gradient is set by consequence severity, not by technical capability:

| Consequence Level | Automation Allowed | HITL Requirement | Examples |
|-------------------|-------------------|------------------|----------|
| **LETHAL** | 0% — AI may present data only | Human initiates ALL actions | Fire control, engagement authorization |
| **SAFETY-CRITICAL** | ≤30% — AI pre-processes, human decides | Human reviews before every action | Target classification, IFF, system fault diagnosis |
| **MISSION-IMPACT** | ≤70% — AI executes routine, flags exceptions | Human reviews exceptions + spot-checks | Scoring, training analytics, sensor calibration |
| **ADMINISTRATIVE** | ≤90% — AI executes, human audits post-hoc | Periodic human audit (weekly) | Logging, data formatting, report generation |

> **Rule:** If consequence level is disputed, default to the MORE restrictive level. Escalate to KN for classification decision.

### P3 — Accountability Cannot Be Delegated to AI

For every AI-generated output, a named human is accountable:

| Output Type | Accountable Human | Accountability Scope |
|-------------|-------------------|---------------------|
| Design documents (Phase 1–4) | KN Nguyen (Chief Engineer) | Technical correctness, standards compliance |
| Deployment artifacts (A1–A5) | KN Nguyen (Project Lead) | Completeness, site-specific accuracy |
| Scoring/assessment outputs | Range Officer (customer) | Tactical validity, qualification decisions |
| Training analytics | Unit Training Officer (customer) | Training program decisions based on AI data |
| Fire control recommendations | Operator on station | Engagement decision — AI provides data only |
| Procurement documents | KN Nguyen | Commercial terms, regulatory compliance |

> **No orphan outputs:** If an AI-generated output has no named accountable human, it SHALL NOT be delivered to a customer or used in a decision.

### P4 — Transparency Over Performance

If forced to choose between a more capable AI system that is opaque and a less capable system that is explainable, Workshop X chooses explainability. Military operators must understand WHY the system recommends what it does.

### P5 — Vietnamese Sovereignty Over Data and Decisions

All training data, scoring data, and personnel performance data generated by Workshop X products SHALL remain under Vietnamese military control. No data leaves Vietnamese territory. No foreign entity has access to operational data. See §5 for technical implementation.

## 2. Ethical Red Lines — What AI Must NEVER Do

These are absolute constraints. No exception process exists. Violation of any red line is a product recall trigger.

| # | Red Line | Enforcement Mechanism |
|---|----------|----------------------|
| RL-1 | AI shall NOT autonomously fire, launch, or release any weapon or munition | Hardware safety interlock + software kill switch + HITL architecture |
| RL-2 | AI shall NOT autonomously classify a person as an enemy combatant | Classification is always "provisional" until human confirms |
| RL-3 | AI shall NOT override a human's decision to abort, cease fire, or stand down | Abort command is hardware-level priority, bypasses all AI processing |
| RL-4 | AI shall NOT transmit operational military data outside the deployed network boundary | Air-gapped architecture + no cloud dependency + data classification enforcement |
| RL-5 | AI shall NOT make qualification/pass/fail decisions on military personnel without human review | All scoring is "preliminary" until Range Officer signs qualification record |
| RL-6 | AI shall NOT suppress, modify, or filter error/fault signals to present a "clean" status | All faults propagate to operator display within 1 heartbeat cycle |
| RL-7 | AI shall NOT continue operating in a safety-critical role after detecting its own malfunction | Self-test failure → immediate fallback to manual mode + operator alert |

### Red Line Verification

Each red line must be verified during Phase 4 (Verification Plan) and re-verified during deployment commissioning:

| Verification Method | Red Lines Covered | Frequency |
|--------------------|-------------------|-----------|
| Architecture review (analysis) | RL-1, RL-2, RL-4, RL-5 | Phase 2 gate + Phase 4 |
| Hardware test (demonstration) | RL-1, RL-3, RL-6, RL-7 | Phase 4 FAT + commissioning |
| Penetration test | RL-4 | Phase 4 + annual |
| Operational scenario test | ALL | Commissioning + annual exercise |

## 3. HITL Architecture — Levels and Placement

### 3.1 HITL Levels

Workshop X products use four HITL levels, each with defined response time and operator cognitive load:

| Level | Name | Operator Action | Max Response Time | Cognitive Load |
|-------|------|----------------|-------------------|----------------|
| **H0** | Full Manual | Operator controls everything; AI off | N/A | HIGH |
| **H1** | AI Inform | AI presents data/recommendation; operator decides and acts | Mission-dependent | MEDIUM-HIGH |
| **H2** | AI Assist | AI pre-computes; operator approves/rejects before execution | ≤5 seconds | MEDIUM |
| **H3** | AI Execute | AI acts within bounded envelope; operator monitors + can override | Continuous monitoring | LOW-MEDIUM |

### 3.2 Product × HITL Level Mapping

| Product | Normal Operation | Degraded Mode | Emergency |
|---------|-----------------|---------------|-----------|
| **V-SMASH** (weapon sight) | H1 — AI computes ballistic solution, shooter fires | H0 — manual backup reticle | H0 — AI off, iron sights |
| **VN-RANGE-001** (scoring) | H3 — AI scores impacts automatically, officer reviews | H1 — AI flags uncertain, officer scores | H0 — manual scoring |
| **CORTEX RANGE** (analytics) | H3 — AI generates reports, trainer reviews | H1 — AI presents raw data, trainer interprets | H0 — no AI, manual AAR |
| **VN-CUAS-001** (detection) | H2 — AI classifies drone, operator confirms before action | H1 — AI presents acoustic data, operator classifies | H0 — audio-only monitoring |
| **VN-12.7MM-SIM** (trainer) | H3 — AI runs simulation, trainee interacts | H1 — instructor takes over scenario | H0 — manual instruction |

### 3.3 HITL Placement Rules

1. **Every transition between consequence levels requires a HITL checkpoint** — AI cannot escalate from MISSION-IMPACT to SAFETY-CRITICAL autonomously
2. **Gate reviews are always H0** — no AI involvement in phase gate decisions
3. **Qualification decisions are always H1 minimum** — AI may present data, human signs
4. **Real-time systems must have a hardware abort** independent of AI software stack
5. **If operator workload exceeds capacity at assigned HITL level, the system must reduce automation (raise HITL level), not skip HITL checks**

## 4. ROE (Rules of Engagement) Compliance

### 4.1 AI and ROE Boundary

ROE interpretation is **exclusively human judgment**. AI may:
- Present sensor data relevant to ROE assessment
- Highlight conditions that may affect ROE applicability (e.g., civilian proximity alert)
- Log ROE-relevant events for post-action review

AI shall NOT:
- Interpret ROE to recommend engagement/non-engagement
- Override or modify ROE parameters set by the commanding officer
- Present target information in a way that implies engagement authorization

### 4.2 ROE-Relevant Product Features

| Product | ROE-Adjacent Feature | Governance Control |
|---------|---------------------|-------------------|
| V-SMASH | Target tracking, ballistic computation | Displayed as "tracking" not "engaging"; no engagement recommendation |
| VN-CUAS-001 | Drone classification (hostile/neutral/friendly) | Classification is always "provisional — confirm with IFF/visual" |
| CORTEX RANGE | Live-fire safety zone monitoring | AI alerts on safety zone breach; cease-fire decision is Range Officer's |

### 4.3 IFF (Identification Friend or Foe) Policy

- All target classifications by AI must include IFF confidence level
- IFF confidence < 95% → MANDATORY human visual/sensor confirmation before any action
- IFF failure mode (cannot determine) → system displays "UNKNOWN" not "NEUTRAL"
- IFF-fails-GREEN pattern (false safe) is the most dangerous failure → always verify with second sensor modality

## 5. Data Sovereignty & Privacy

### 5.1 Legal Framework

| Law/Regulation | Key Requirement | Workshop X Compliance |
|----------------|----------------|----------------------|
| **Luật An Ninh Mạng 2018** (Art. 23) | Domestic data storage | Air-gapped edge server — all data stays on-premises |
| **Luật An Ninh Mạng 2018** (Art. 26) | Data classification | Training data = RESTRICTED; encrypted AES-256 at rest |
| **Luật An Ninh Mạng 2018** (Art. 35) | Annual security audit | Audit plan included in deployment contract |
| **NĐ 13/2023/NĐ-CP** | Personal data protection | Soldier performance data: RBAC, audit logging, deletion rights |
| **TCVN 11930:2017** | ISMS framework | Applied to CORTEX RANGE deployment |

### 5.2 Data Classification

| Classification | Definition | Handling | Products |
|---------------|------------|----------|----------|
| **RESTRICTED** | Training performance data, scoring records, qualification results | Encrypted at rest + in transit; RBAC; no export; annual audit | CORTEX, VN-RANGE |
| **INTERNAL** | System configuration, calibration data, maintenance logs | On-premises only; standard access control | ALL |
| **PUBLIC** | Product specifications, marketing materials, published standards | No restrictions | Marketing docs |

### 5.3 Data Sovereignty Controls

| Control | Implementation | Verification |
|---------|---------------|-------------|
| No cloud dependency | All AI inference runs on-device (Hailo-8) or on-premises (edge server) | Architecture review + network audit |
| No telemetry home | Products do not phone home to Workshop X or any third party | Network traffic analysis during commissioning |
| Data ownership clause | Contract §7: "All data generated by the system is property of [customer unit]" | Contract review |
| Right to deletion | Customer can wipe all data via factory reset; verified by checksum | Functional test during FAT |
| No foreign access | System admin credentials held by customer IT; Workshop X has no remote access | Access audit during commissioning |

## 6. AI Output Classification & Handling

### 6.1 Output Types and Required Review

| Output Type | AI Confidence Allowed | Human Review Before Use | Retention |
|-------------|----------------------|------------------------|-----------|
| Safety-critical recommendation | Must show evidence tier (L1–L5) | MANDATORY — named reviewer signs | Permanent |
| Scoring/assessment | Numerical confidence + uncertainty band | MANDATORY for qualification; optional for practice | Per customer retention policy |
| Training analytics | Statistical confidence interval | Recommended — trainer review | Session + aggregation period |
| Design document | Self-assessed via QC Gate (P44) | MANDATORY — KN reviews all | Project archive (permanent) |
| System diagnostic | Fault probability + sensor source | Automatic for LOG level; human for WARN/ERROR | 90-day rolling + incident archive |

### 6.2 AI Output Labeling

Every AI-generated output delivered to a military customer must carry:

```
┌─────────────────────────────────────────────────┐
│ AI-GENERATED OUTPUT — REQUIRES HUMAN REVIEW      │
│ System: [product name] v[version]                │
│ Generated: [timestamp UTC+7]                     │
│ Confidence: [score] based on [evidence tier]     │
│ Reviewed by: [name] on [date] — [APPROVED/REJECTED] │
│ Classification: [RESTRICTED/INTERNAL/PUBLIC]     │
└─────────────────────────────────────────────────┘
```

> **Rule:** If the label is missing, the output is NOT approved for use. No exceptions.

## 9. Incident Response — AI Governance Failures

### 9.1 Severity Classification

| Severity | Definition | Response Time | Escalation |
|----------|------------|---------------|-----------|
| **SEV-1** | Red line violation (RL-1 through RL-7) | IMMEDIATE — stop operations | KN + customer CO + MoND if applicable |
| **SEV-2** | HITL bypass — AI acted without required human review | 4 hours | KN + customer technical officer |
| **SEV-3** | Data sovereignty breach — data left network boundary | 4 hours | KN + customer IT + legal |
| **SEV-4** | Governance process gap — output delivered without label/review | 24 hours | KN — internal process fix |
| **SEV-5** | Near-miss — governance control caught an issue before impact | 1 week | KN — log and learn |

### 9.2 Response Protocol

1. **Contain** — isolate the affected system/output
2. **Assess** — determine severity, scope, and root cause
3. **Notify** — escalate per severity table above
4. **Remediate** — fix the root cause (not just the symptom)
5. **Log** — add to Governance Decision Log with full detail
6. **Prevent** — update this framework, QC Gate, or product design to prevent recurrence
