# Deep Content Analyzer

Transform any intellectual content (articles, book chapters, podcast transcripts, frameworks) into comprehensive, actionable insight documents using integrated Systems Thinking + Meta-Learning analysis + First-Principles Debate + ARCHITECT Framework generation.

## When to Use

**Always trigger when:**
- User pastes article/chapter/transcript text + requests analysis
- User says "analyze", "break down", "extract insights", "clarify and exemplify"
- User provides content + requests "use all frameworks" or names specific skills
- User references past analysis pattern ("like you did with Naval/Profit First/BASB")
- User says "debate", "first principles", "expand framework", "ARCHITECT"
- User says "bổ sung", "tranh luận", "mở rộng"

**Content types this skill handles:**
- Business/entrepreneurship articles and book chapters
- Technical/engineering thought pieces
- Personal development and mental model frameworks
- AI/technology trend analysis
- Any knowledge-dense content worth systematic extraction

## Core Philosophy

Most content analysis produces shallow summaries. This skill produces **deep structural understanding** by:

1. **Revealing system dynamics** hidden in the prose (stocks, flows, loops, archetypes)
2. **Identifying leverage points** where small interventions create large effects
3. **Building learning infrastructure** (mnemonics, drills, rubrics) so insights stick
4. **Generating counter-intuitive insights** that surface-reading misses
5. **Creating actionable use cases** for specific audience profiles
6. **Debating the content's claims** from first principles to distinguish truth from convention
7. **Generating an expanded ARCHITECT-style framework** that goes beyond what the author provides

The output should surprise and inform even someone who has already read the source material carefully.

### PHASE 2: CONTENT EXTRACTION (10 min conceptual time)

Before applying frameworks, extract the raw materials from the source content:

**Step 2.1: Identify the Core Thesis**
- What is the author's single most important claim?
- What problem are they solving?
- What paradigm shift are they proposing (if any)?
- What is the stated vs. real goal of the content?

**Step 2.2: Extract System Variables**
Read the content looking for:
- **Stocks** — What accumulates? (knowledge, debt, trust, capability, risk)
- **Flows** — What changes those stocks? (learning rates, decay rates, investment rates)
- **Delays** — Where are time lags between cause and effect?
- **Feedback dynamics** — What reinforces? What balances? What spirals?
- **Constraints** — What limits the system's throughput?

**Step 2.3: Extract Learning Content**
Read the content looking for:
- **Core concepts** (chunk candidates — groups of 5-9 related ideas)
- **Prerequisite chains** (what must be understood before what)
- **Common mistakes** the author warns about
- **Actionable principles** vs. theoretical background
- **Audience assumptions** (who is this written for?)

**Step 2.4: Identify What's Missing (Critical for Phase 4)**
Critically evaluate — this feeds directly into the First-Principles Debate:
- What does the author assume but never state?
- What counter-arguments exist?
- What adjacent domains illuminate the topic?
- What system archetypes are present but unnamed?
- What would change if you applied first-principles reasoning?
- What are the CURRENT limitations cited vs. FUNDAMENTAL limitations?
- What rate-of-change dynamics does the author treat as static?
- What dimensions does the author ignore entirely?

### PHASE 3: FRAMEWORK APPLICATION (Main analysis)

Apply each framework systematically. Not every framework produces equal insight for every piece of content — emphasize the ones that reveal the most.

#### 3A: Systems Thinking Analysis

**Stock-Flow Map (from stock-flow-mapper skill):**
For each critical stock identified in Step 2.2:
```
Stock: [Name]
Current Level: [High/Medium/Low]
Units: [specific measurement]
Type: [Buffer/Constraint]

Inflows:
  1. [Name] — Rate: [Fast/Med/Slow] — Control: [what governs] — Delay: [duration]
  
Outflows:
  1. [Name] — Rate: [Fast/Med/Slow] — Control: [what governs] — Delay: [duration]

Pattern: [Growth/Depletion/Equilibrium/Oscillation]
```

Target: 4-7 stocks mapped with full flow details. Rank by system impact.

**Feedback Loop Detection (from feedback-loop-detector skill):**
Map causal links between stocks using:
- `[A] +→ [B]` = same direction
- `[A] −→ [B]` = opposite direction
- Mark delays with `||`

Classify loops:
- Reinforcing (R1, R2...): Even number of negative links
- Balancing (B1, B2...): Odd number of negative links

For each loop: Name descriptively, assess Strength × Speed × State = Dominance

Target: 3-7 loops detected. Create dominance ranking table.

**System Archetype Detection (from feedback-loop-detector skill):**
Match loop structures against known archetypes:
- Shifting the Burden (most common in these analyses)
- Fixes That Fail
- Escalation
- Success to Successful
- Eroding Goals
- Tragedy of Commons

Provide: Pattern description, evidence from content, confidence level, counter-strategy.

**Leverage Point Analysis (from meadows-leverage-analyzer skill):**
Scan for L1-L12 presence, prioritize high leverage:
- L1-L3 (Paradigm, Mindset, Goals) — prioritize always
- L4-L6 (Self-organization, Rules, Information) — high ROI
- L7-L9 (Loop gain, Loop strength, Delays) — structural
- L10-L12 (Physical structure, Buffers, Parameters) — last resort

For each identified leverage point:
```
L[X]: [Name] — Priority: [HIGH/MED/LOW]
Evidence: [Quote or observation from content]
Intervention: [Specific, actionable recommendation]
Expected Impact: [Cascade effects]
Timeline: [When results expected]
```

Target: 5-8 leverage points ranked. Design Phase 1-3 intervention cascade.

#### 3B: Meta-Learning Framework Application

**Feynman Clarification:**
- 60-second explanation (no jargon)
- Everyday analogy (kitchen, sports, construction — something visceral)
- Domain-specific example (if applicable to user's context)
- 3 diagnostic questions at increasing depth (comprehension → application → system-level)

**Chunking Breakdown:**
- Break content into 4-8 learning chunks
- Each chunk: 5-9 core concepts, prerequisites, estimated time
- Map dependency hierarchy (what must come before what)
- Identify optimal learning sequence (often different from presentation order)

**Mnemonic Creation:**
- Create 1-2 memorable acronyms for the core framework
- Follow MEMORABLE criteria (Meaningful, Emotional, Manageable, etc.)
- Provide both the mnemonic and retrieval instructions

**Self-Assessment Rubric:**
- 6-10 dimensions relevant to the content
- 3 scoring levels per dimension (Novice/Competent/Expert)
- Behavioral indicators (not just knowledge — what does competence look like?)
- Scoring bands with interpretation

**Interleaving Schedule:**
- 4-16 week schedule mixing topics
- Morning/afternoon block structure
- Daily practice focus
- No two consecutive blocks on same primary topic

**Targeted Drills:**
- 2-5 specific practice exercises
- Focus on the highest-leverage skills or most common failure points
- Progressive difficulty (Week 1-2 → Week 3-4 → Week 5+)
- Each drill: purpose, duration, instructions, scoring criteria

**Learning Journal Template:**
- 5-7 reflection prompts tied to the content's key dynamics
- Include at least one prompt about feedback loops
- Include at least one prompt about meta-learning (learning about learning)

**Additional frameworks (apply when relevant):**
- Learning Architecture: Full pathway with time estimates if content is complex enough
- Design Review: Strengths/weaknesses of the author's framework
- Concept Evaluation: What's right, what's wrong, what's missing
- Progress Tracking: Competency grid for skill development
- Focus Session Design: Optimal practice block structure

### PHASE 4: FIRST-PRINCIPLES DEBATE + ARCHITECT FRAMEWORK (Core, NOT Optional)

This phase is what elevates the analysis from "comprehensive summary" to "original intellectual contribution." It should ALWAYS be included for any content that makes claims, predictions, or proposes frameworks — which is nearly all content worth analyzing.

#### 4A: First-Principles Debate Process

For each major claim in the content, apply this rigorous 6-step deconstruction:

**Step 1: State the Claim Precisely**
Strip away rhetoric, metaphor, and persuasive framing. What is the author actually asserting as true?

**Step 2: Decompose to Fundamentals**
Ask: "What would have to be true for this claim to hold?" Break the claim into its foundational assumptions. Identify which assumptions are:
- **Axiomatic** (self-evident, definitionally true)
- **Empirical** (testable, currently supported by evidence)
- **Conventional** (widely believed but not necessarily true from first principles)
- **Speculative** (projection or prediction without strong evidence)

**Step 3: Apply the Current vs. Fundamental Limitation Test**
This is the most critical analytical move. For any limitation the author cites:
```
CURRENT LIMITATION (will eventually be overcome):
- Technology isn't there yet but trajectory is clear
- Scaling/cost barriers that reduce over time
- Regulatory gaps that will be filled
→ DON'T bet your career/strategy on current limitations lasting

FUNDAMENTAL LIMITATION (physics-level constraint):
- Requires something that computation fundamentally cannot provide
- Violates information-theoretic limits
- Requires embodiment, consciousness, or social cognition hardware
- Requires genuine skin-in-the-game (consequences for the entity)
→ SAFE to build strategy on these lasting
```

**Step 4: Apply Rate-of-Change Analysis**
The author likely treats dynamic variables as static. Identify:
- What rates of change does the author ignore?
- What boundaries does the author assume are fixed but are actually moving?
- What is the relationship between relevant rates?
  - dH/dt (human capability change rate)
  - dA/dt (agent/technology capability change rate)  
  - dR/dt (regulatory/institutional change rate)
  - dM/dt (market/competitive change rate)
- Define the survival/success condition in terms of these rates

**Step 5: Identify Missing Dimensions**
Systematically check for dimensions the author ignores. Use this checklist:

```
DIMENSION CHECKLIST:
□ Taste/Aesthetic Judgment — Does the content ignore the difference between 
  "correct" and "excellent"?
□ Skin in the Game — Does the content ignore that entities with consequences 
  decide differently than entities without?
□ Compound Stack Effect — Does the content treat skills as independent rather 
  than multiplicative combinations?
□ Trust Capital — Does the content ignore trust as a slowly-built, 
  instantly-depletable asset?
□ Physical-World Interface — Does the content ignore embodiment and 
  real-world constraints?
□ Organizational Power Dynamics — Does the content treat change as purely 
  technical rather than political?
□ Information Asymmetry — Does the content ignore who has context vs. data?
□ Regulatory Dynamics — Does the content ignore the regulatory window?
□ Co-Evolution — Does the content treat human-technology relationship as 
  static rather than co-evolutionary?
□ Second-Order Effects — Does the content ignore what happens AFTER the 
  proposed solution is implemented?
□ Temporal Dynamics — Does the content provide a snapshot instead of 
  tracking how the situation evolves over time?
□ Selection Bias — Does the author only look at evidence that supports 
  their thesis?
```

**Step 6: Generate Debate Points**
For each significant gap found in Steps 2-5, generate a formal debate point:

```
## Debate Point N: [Title — one sentence that captures the counter-argument]

**The article's claim:** [Precise statement of what the author asserts]

**First-principles counter-argument:**
[2-4 paragraphs explaining WHY the claim is incomplete, wrong, or misleading 
from first principles. Use physics analogies, rate-of-change analysis, 
information theory, or constraint theory as appropriate.]

**The corrected frame:**
[1-2 paragraphs providing the more accurate version of the claim]

**Systems Thinking Integration:**
[How this debate point connects to stocks, flows, loops, or leverage points 
identified in Phase 3]
```

Target: 3-7 debate points, ranked by significance. At least one should address rate-of-change dynamics, and at least one should identify a missing dimension.

#### 4B: ARCHITECT Framework Generation

After the debate reveals what's missing, synthesize everything into an expanded framework that goes BEYOND the original content. This is the signature output that transforms analysis into original intellectual contribution.

**The ARCHITECT pattern is a general-purpose framework generator.** It takes the original content's insights PLUS the debate's corrections and synthesizes them into a new, complete framework. The framework name itself should be a meaningful mnemonic.

**Step 1: Identify the Irreducible Elements**
From the debate, identify the minimum set of capabilities/principles/components that cannot be further reduced. Group the author's original items into these irreducible elements. Typically this reduces the original list by 30-60%.

```
ORIGINAL AUTHOR'S MODEL:
[List their items — typically 5-12 items in a flat list]

FIRST-PRINCIPLES REDUCTION:
[Group into 3-5 irreducible elements with hierarchy]

WHY THE REDUCTION MATTERS:
[Explain what the reduction reveals that the flat list obscures]
```

**Step 2: Design the Framework Architecture**
Structure the irreducible elements into a system:
- Define **layers** (what builds on what — dependency hierarchy)
- Define **flows** between layers (how capability in one enables capability in another)
- Identify the **substrate** (the meta-capability that enables all others)
- Identify the **output** (what the complete system produces)

```
┌─────────────────────────────────────────────┐
│     LAYER N: [Highest-level capability]     │
│     [Components at this level]              │
├─────────────────────────────────────────────┤
│     LAYER N-1: [Supporting capability]      │
│     [Components at this level]              │
├─────────────────────────────────────────────┤
│     ...                                     │
├─────────────────────────────────────────────┤
│     LAYER 1: [Foundation capability]        │
│     [Components at this level]              │
└─────────────────────────────────────────────┘
         ↑ Substrate: [META-CAPABILITY]
         
OUTPUT: [What the complete system produces]
```

**Step 3: Create the Framework Mnemonic**
The framework name should be an acronym where each letter maps to a principle or component. Requirements:
- Meaningful word (not random letters)
- Connected to the domain (e.g., ARCHITECT for building, PLATES for financial allocation)
- Each letter maps to a specific, memorable principle
- Can be read both as a word AND as a list of components
- Include both the mnemonic AND retrieval instructions (how to recall what each letter means)

**Step 4: Map the Complete System Dynamics**
For the expanded framework, provide the FULL system map including:

**All Feedback Loops (R + B):**
Create a complete inventory table:

```
| Loop | Name | Structure | Speed | Dominance | Status |
|------|------|-----------|-------|-----------|--------|
| R1   | [Descriptive name] | [A → B → C → A] | Fast/Med/Slow | HIGH/MED/LOW | Active/Dormant |
```

Include loops from BOTH the original analysis (Phase 3) AND new loops discovered during the debate (Phase 4A). Target: 5-10 loops total.

**All System Archetypes:**

```
| Archetype | Where It Appears | Danger Level | Counter-Strategy |
|-----------|-----------------|--------------|-----------------|
| [Name]    | [Evidence]      | CRITICAL/HIGH/MED | [Specific counter-action] |
```

**Step 5: Generate the Complete Leverage Point Cascade**
Expand the Phase 3 leverage points by incorporating debate findings:

**Phase 1: Quick Wins (Week 1-4)**
Target: L2 (Paradigm) + L6 (Information Flow)

| # | Intervention | Leverage | Expected Impact | Pilot Action |
|---|-------------|----------|----------------|-------------|
| 1 | [Specific] | L[X] | [Quantified] | [Concrete first step] |

**Phase 2: Structural Lock-In (Week 5-12)**
Target: L5 (Rules) + L7 (R Loop Gain) + L8 (B Loop Strength)

**Phase 3: Systemic Transformation (Month 4-6)**
Target: L3 (Goals) + L4 (Self-Organization) + L10 (Structure)

Each phase must include: specific interventions, leverage point justification, expected impact, and pilot actions.

**Step 6: Build the Extended Self-Assessment Rubric**
Expand the Phase 3 rubric to cover the ARCHITECT framework dimensions:

```

|-----------|----------------|---------------|-----------------|
| [Each letter of the mnemonic] | [Behavioral description] | [...] | [...] |
```

Scoring bands:
- [Low range]: EXPOSED — immediate action needed
- [Mid range]: TRANSITIONING — focus on weak dimensions
- [High range]: POSITIONED — compound and teach others
- [Top range]: ANTIFRAGILE — improvement in environment makes you stronger

**Step 7: Design Targeted Drills for the ARCHITECT Framework**
Create 3-7 drills that specifically build the capabilities identified in the expanded framework. Each drill must:
- Target a specific dimension of the ARCHITECT mnemonic
- Be doable in 15-90 minutes
- Have progressive difficulty
- Include scoring/assessment criteria
- Connect to a specific feedback loop or leverage point

```
**Drill N: "[Descriptive Name]" ([Frequency], [Duration])**

Progression:
- Week 1-2: [Beginner version]
- Week 3-4: [Intermediate version]
- Week 5+: [Advanced version]

Scoring: [How to know if you're improving]
```

**Step 11: Distill into Three Laws**

## Execution Notes

**For Claude using this skill:**

1. **Read the skill files first.** Every time. The templates and checklists in the individual skill files produce measurably better output. Don't skip this step to save time — it's the highest-leverage action.

2. **Create the output as a .md file.** Always save to `/mnt/user-data/outputs/` and use `present_files`. The analysis is too long for chat display and the user needs the file.

3. **Name files descriptively.** Pattern: `[Content_Title]_Full_Analysis_with_ARCHITECT.md`

4. **The First-Principles Debate is NOT optional.** Every content piece worth analyzing has debatable claims. If you think there's nothing to debate, you haven't looked hard enough. At minimum, check rate-of-change dynamics and the Current vs. Fundamental limitation test.

5. **The ARCHITECT framework must ADD new value.** If the expanded framework just restates the original content in a different format, it has failed. The framework must include at least 2-3 dimensions that the original author completely ignored.

6. **Spend time on the Three Laws.** These are the distilled output of the entire analysis. They should be pithy enough to remember, deep enough to generate the full framework when unpacked, and non-obvious enough to surprise.

7. **Cross-reference previous analyses for patterns.** The user has a growing library of these analyses. Look for recurring archetypes and recurring missing dimensions across analyses.

8. **The debate should be genuinely rigorous.** Don't create strawman arguments or find trivial errors. Look for structural flaws in the author's reasoning that, once identified, fundamentally change how the reader should apply the content.

9. **Physics analogies are powerful.** Analogies to thermodynamics (entropy, equilibrium), mechanics (forces, friction, momentum), information theory (compression, bandwidth, noise), and evolution (selection pressure, adaptation, fitness landscape) consistently produce the deepest insights.

10. **Rate-of-change is the secret weapon.** Most authors describe snapshots. Analyzing rates of change — what's accelerating, what's decelerating, what's the relationship between rates — reveals dynamics that snapshot-thinking completely misses.
