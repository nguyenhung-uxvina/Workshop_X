## Executive Summary

Section 6.4.2 addresses a critical pivot point in systematic design: transforming individual working principles into coherent working structures through system synthesis. This section teaches how to use the morphological matrix (Zwicky scheme) to systematically combine compatible solutions into overall concepts, then select promising combinations for further development.

**Key Insight:** The morphological matrix is not just a creativity tool—it's a compatibility engine that forces designers to confront physical and geometrical constraints BEFORE committing to detailed design.

## 1. FEYNMAN TECHNIQUE: Simple Explanation

### 💡 60-Second Explanation

**"Combining Working Principles" is like assembling a meal from a menu with multiple categories.**

Imagine a restaurant menu where you MUST pick one item from each category (appetizer, main, side, dessert). You can't just pick random items—some combinations don't work (ice cream with soup makes a mess). The morphological matrix is that menu: rows are categories (subfunctions), columns are options (working principles), and you draw a line connecting compatible choices to create a "meal" (working structure).

### 🏠 Everyday Analogy: The Build-Your-Own-Burger Bar

At a burger restaurant:
- **Rows** = Categories: Bun type, Patty, Cheese, Toppings, Sauce
- **Columns** = Options within each category
- **Compatibility** = Pretzel bun + BBQ sauce + onion rings = YES ✓; Fish patty + sweet bun + ketchup = NO ✗
- **Working Structure** = Your final burger combination

Just as you wouldn't put ice cream between burger buns, you wouldn't combine a hydraulic lift mechanism with an electrical signal output that has no hydraulic pressure sensor.

### 🎯 Defense Application: LOMAH System Concept Development

For a Location of Miss And Hit (LOMAH) system:

| Subfunction | Option 1 | Option 2 | Option 3 | Option 4 |
|:---|:---|:---|:---|:---|
| Detect projectile | Acoustic sensors | Optical break-beam | Radar doppler | IR thermal |
| Calculate trajectory | FPGA processing | DSP chip | Embedded PC | Cloud edge |
| Locate impact | Triangulation | Time-of-arrival | Image analysis | Vibration mapping |
| Display result | LED matrix | LCD screen | AR overlay | Remote tablet |

**Combination A:** Acoustic → FPGA → Triangulation → LED matrix (low-cost, field-rugged)  
**Combination B:** Optical → DSP → Image analysis → AR overlay (high accuracy, complex)

### ❓ Quick Understanding Check

**Question:** Why can't you just pick the "best" option in each row and combine them?

**Expected Answer:** Because "best" in isolation doesn't mean "best together." The options must be physically, geometrically, and functionally compatible. A radar doppler detector might be excellent alone but incompatible with a simple triangulation calculation method.

### ⚠️ Common Misconceptions

| Misconception | Reality |
|:---|:---|
| "More options per row = better" | Quality over quantity. 4-6 well-developed options beat 20 vague ones |
| "Any combination is theoretically valid" | No—compatibility constraints eliminate most combinations |
| "The matrix generates concepts automatically" | No—human judgment selects compatible paths |
| "One combination is obviously best" | Rarely—multiple valid concepts usually exist |

### Chunk 1: System Synthesis Concept
**Duration:** 45 min | **Difficulty:** ⭐⭐

**Prerequisites:** Understanding of working principles (6.4.1)

**Core Concepts (7 items):**
1. Working structure definition (tổng hợp hệ thống)
2. System synthesis vs. component selection
3. Combinatorial complexity (N = m₁ × m₂ × ... × mₙ)
4. Theoretical vs. practical search field
5. Function structure as combination basis
6. Compatibility requirements
7. Energy-Material-Signal flow continuity

**Explanation:**

System synthesis transforms isolated working principles into integrated working structures. The function structure established in Section 6.3 provides the logical foundation—each subfunction requires a working principle, and these principles must work together as a coherent system.

The key insight is that combination is NOT arbitrary. If you have 6 subfunctions with 4 options each, theoretical combinations = 4⁶ = 4,096 possibilities. But physical and geometrical constraints typically reduce this to 5-10 viable combinations.

**Defense Application:**
For a 12.7mm Remote Controlled Weapon Station (RCWS):
- Subfunctions: Aim, Stabilize, Fire, Reload, Protect, Control
- Each has 3-5 working principles
- Theoretical combinations: 3×4×4×3×4×5 = 2,880
- After compatibility screening: ~8-12 viable concepts

**Practice Exercise:**
Calculate theoretical combinations for a Training Grenade system with these subfunctions: Generate cue (3 options), Delay timing (4 options), Create effect (5 options), Reset mechanism (3 options). Answer: 3×4×5×3 = 180

**Connection to Next Chunk:** Now that you understand WHY system synthesis matters, Chunk 2 teaches HOW to structure the morphological matrix.

### Chunk 2: Morphological Matrix Structure
**Duration:** 60 min | **Difficulty:** ⭐⭐

**Prerequisites:** Chunk 1, Function structure basics

**Core Concepts (8 items):**
1. Zwicky classification scheme (sơ đồ phân loại Zwicky)
2. Row organization (subfunctions)
3. Column organization (solution principles)
4. Entry format (words + sketches)
5. Ordering by function structure sequence
6. Energy-Material-Signal flow separation
7. Additional column parameters
8. Visual clarity requirements

**Explanation:**

The morphological matrix is a structured table where:
- **Rows** = Subfunctions from the function structure, ordered by logical flow
- **Columns** = Working principles that fulfill each subfunction
- **Cells** = Specific solutions with sketches AND descriptions

Critical organization principles:
1. List subfunctions in the order they appear in function structure
2. Separate E-M-S flows if helpful for clarity
3. Arrange column solutions using additional parameters (energy type, mechanism type)
4. Always include rough sketches—words alone are insufficient for compatibility assessment

**Defense Application:**
For a UAV Catapult system, the matrix structure:

| Subfunction | Pneumatic | Elastic | Electromagnetic | Hydraulic |
|:---|:---|:---|:---|:---|
| Store energy | Air tank | Bungee bundle | Capacitor bank | Accumulator |
| Release energy | Valve trigger | Latch release | IGBT switch | Solenoid valve |
| Guide UAV | Rail track | V-groove | Magnetic guide | Tube launcher |
| Absorb recoil | Pneumatic damper | Spring return | Eddy current | Hydraulic cushion |

Notice how column headers use energy type as organizing parameter, making compatibility assessment easier.

**Practice Exercise:**
Create the row structure (subfunctions only) for a Naval Weapon Simulator that must: Present target, Simulate weapon response, Calculate hit/miss, Provide feedback. List at least 3 working principles per subfunction.

**Connection to Next Chunk:** With matrix structure understood, Chunk 3 teaches the critical skill of compatibility verification.

### Chunk 3: Compatibility Verification
**Duration:** 75 min | **Difficulty:** ⭐⭐⭐

**Prerequisites:** Chunks 1-2, E-M-S flow understanding

**Core Concepts (9 items):**
1. Physical compatibility (tương thích vật lý)
2. Geometrical compatibility (tương thích hình học)
3. E-M-S flow continuity verification
4. Compatibility matrix construction
5. Interface requirement identification
6. Neighboring subfunction analysis
7. Documentation of incompatibilities
8. Iteration with function structure
9. Sketch-based verification

**Explanation:**

Compatibility verification is the CRITICAL filter that reduces thousands of theoretical combinations to dozens of practical ones. Incompatibility sources:

**Physical Incompatibility:**
- Conflicting energy forms (hydraulic principle feeding electrical principle with no converter)
- Material state mismatch (solid particle output feeding liquid input)
- Signal form mismatch (analog output to digital-only input)

**Geometrical Incompatibility:**
- Spatial interference (two components can't occupy same space)
- Access conflicts (maintenance path blocked by adjacent principle)
- Flow path discontinuity (output location doesn't reach input)

**Verification Method:**
1. For each pair of neighboring subfunctions, ask: "Can the output of principle A become the input of principle B?"
2. Create compatibility matrix showing which principle combinations are valid
3. Document WHY incompatible combinations fail (for future reference)
4. Iterate: If no compatible path exists, either revise function structure or search for additional working principles

**Defense Application:**
For Target USV, checking compatibility between "Propel vessel" and "Control direction":

| Propulsion ↓ / Steering → | Rudder | Differential thrust | Water jet deflection | Pod rotation |
|:---|:---|:---|:---|:---|
| Single outboard | ✓ | ✗ (one motor) | ✗ | ✗ |
| Twin outboard | ✓ | ✓ | ✗ | ✗ |
| Water jet | ✗ (no prop wash) | ✓ | ✓ | ✗ |
| Azimuth pod | ✗ | ✗ | ✗ | ✓ |

**Practice Exercise:**
For a Towed Target system, verify compatibility between "Generate motion" (winch-pull vs. vessel-tow vs. self-propelled) and "Maintain altitude" (hydrodynamic lift vs. dynamic buoyancy vs. active control). Document which combinations are physically compatible.

**Connection to Next Chunk:** With compatibility verified, Chunk 4 teaches how to select the most promising combinations from valid options.

### Chunk 4: Selection of Promising Combinations
**Duration:** 60 min | **Difficulty:** ⭐⭐⭐

**Prerequisites:** Chunks 1-3, Requirements list basics

**Core Concepts (8 items):**
1. Selection chart methodology
2. Requirements list screening
3. Budget constraint filtering
4. Technical feasibility assessment
5. Economic viability quick-check
6. Documentation of rejection reasons
7. Preference indication
8. Concentration on promising combinations

**Explanation:**

After compatibility filtering, multiple valid combinations typically remain. Selection uses these criteria:

**First Filter - Requirements Compliance:**
- Does combination meet ALL demands (musts)?
- If any demand is violated, combination is eliminated
- Document which demand caused rejection

**Second Filter - Budget Reality:**
- Rough cost estimate for each combination
- Eliminate combinations clearly exceeding budget
- Don't need precision—order of magnitude sufficient

**Third Filter - Technical Feasibility:**
- Is the technology mature enough for timeline?
- Are required skills available in-house or accessible?
- Does supply chain exist (especially critical for Vietnamese context)?

**Fourth Filter - Preference Indication:**
- Among remaining combinations, which show most promise?
- Consider: performance potential, risk level, innovation value
- Select 2-4 combinations for detailed concept development

**Defense Application:**
For RAMS (Real-Time AI-Driven Marksmanship Training System):

| Combination | Demands Met? | Budget OK? | Tech Ready? | Preferred? |
|:---|:---|:---|:---|:---|
| A: Camera + Cloud AI + LED feedback | Latency demand violated (>100ms) | Yes | Yes | ✗ |
| B: LiDAR + Edge AI + AR display | All met | Over budget | Yes | ✗ |
| C: Camera + Edge AI + Haptic vest | All met | Yes | Low TRL | - |
| D: IMU + Edge AI + Audio feedback | All met | Yes | Yes | ✓✓ |
| E: Camera + Edge AI + Projector | All met | Yes | Yes | ✓ |

Result: Pursue combinations D and E for concept development.

**Practice Exercise:**
Apply selection criteria to 4 combinations for a Small Arms Simulator: (A) Laser-based + pneumatic recoil, (B) Camera-based + electric recoil, (C) Optical fiber + mechanical return, (D) Infrared + no recoil. Assume budget constraint of $5,000/unit and demands for realistic feedback and <50ms latency.

**Connection to Next Chunk:** Selected combinations need defense-specific validation before concept development.

### Chunk 5: Defense-Specific Integration
**Duration:** 90 min | **Difficulty:** ⭐⭐⭐⭐

**Prerequisites:** Chunks 1-4, MIL-STD awareness

**Core Concepts (9 items):**
1. MIL-STD-810 environmental compatibility
2. STANAG interoperability requirements
3. Supply chain restrictions (export controls)
4. Vietnamese manufacturing capability mapping
5. Three-level maintenance philosophy
6. Technology transfer potential
7. Indigenous development priority
8. Tropical environment adaptation
9. Cost-effectiveness for defense budgets

**Explanation:**

Vietnamese defense applications add specific compatibility layers beyond basic technical compatibility:

**Environmental Compatibility (MIL-STD-810):**
- Combinations must survive: High temp (49°C+), humidity (95%+), salt fog, fungus
- Some working principles fail environmental screening (e.g., certain adhesives)
- Add "environmental compatibility" as additional compatibility dimension

**Supply Chain Compatibility:**
- Export-controlled components limit some combinations
- Indigenous alternatives may exist with different performance
- Map each working principle to supply chain source

**Manufacturing Compatibility:**
- Does Vietnam have capability to produce this combination?
- If not, is technology transfer feasible?
- Joint venture requirements?

**Maintenance Compatibility:**
- Can combination be maintained at all three levels (organizational, intermediate, depot)?
- Are test equipment and spares available locally?

**Defense Application:**
For Radar-IR Target Simulation drone:

| Combination | MIL-810 OK? | Supply Chain | VN Manufacturing | Maintenance |
|:---|:---|:---|:---|:---|
| Corner reflector + chemical flare | Yes | Domestic | Yes | Simple |
| Luneberg lens + pyro IR | Yes | Import restricted | No | Complex |
| Active RCS + electric heater | Humidity concern | Available | Possible JV | Medium |
| Chaff/flare dispenser | Yes | Licensed | Yes | Standard |

**Practice Exercise:**
Evaluate a Tethered Drone combination for Vietnamese production: (A) COTS drone + local tether vs. (B) Custom airframe + imported tether system. Consider supply chain risk, maintenance capability, and technology transfer.

**Connection to Next Chunk:** Final integration ensures combinations translate to complete working structures.

### Chunk 6: Working Structure Documentation
**Duration:** 60 min | **Difficulty:** ⭐⭐⭐

**Prerequisites:** Chunks 1-5, Technical drawing basics

**Core Concepts (7 items):**
1. Principle solution representation
2. Working structure sketch requirements
3. Energy-Material-Signal flow annotation
4. Interface documentation
5. Traceability to function structure
6. Variant comparison format
7. Handover to embodiment design

**Explanation:**

The output of Section 6.4.2 is NOT a complete design—it's a documented working structure ready for embodiment design. Documentation requirements:

**Sketch Requirements:**
- Show ALL subfunctions implemented
- Indicate working principle for each
- Draw physical arrangement (rough proportions acceptable)
- Label major components with function names

**Flow Annotation:**
- Energy flow: solid arrows
- Material flow: dashed arrows
- Signal flow: dotted arrows
- Show continuity from input to output

**Interface Documentation:**
- Mark interfaces between working principles
- Note any conversion elements (transducers, converters)
- Identify potential integration challenges

**Traceability:**
- Reference back to function structure (which subfunction does each principle fulfill?)
- Document selection rationale (why this combination?)
- Note rejected alternatives and reasons

**Defense Application:**
For Transport (Cargo) Drone working structure documentation:

```
Working Structure: TD-Concept-C
───────────────────────────────────────
Function Structure Ref: TD-FS-v2.1
Combination Path: A3-B2-C4-D1-E3-F2

[Rough sketch showing:]
- Lift: Quad rotor (A3) ──Energy──→ Motor controllers
- Navigate: GPS/INS (B2) ──Signal──→ Flight controller  
- Carry load: Belly pod (C4) ──Material──→ Release mechanism
- Deploy: Winch lower (D1) ──Energy──→ Payload position
- Return: Autonomous RTB (E3) ──Signal──→ Ground station
- Land: VTOL pad (F2) ──Material──→ Recovery

Key Interfaces:
• Power distribution hub (energy routing)
• CAN bus (signal integration)
• Mechanical hardpoints (material attachment)

Selection Rationale:
• Quad rotor chosen for VTOL requirement (coastal ops)
• Winch lower chosen for precision placement (medical supply)
• GPS/INS chosen for navigation accuracy requirement

Rejected: Hexa-rotor (A4) - exceeds weight budget
Rejected: Free-drop (D2) - violates accuracy demand
```

**Practice Exercise:**
Document a working structure for an AR-VR Weapon Simulator showing: Visual presentation principle, Haptic feedback principle, Tracking principle, and Scoring principle. Include E-M-S flow annotations.

## 3. DESIGN REVIEW CRITERIA

### Review Checklist for Morphological Matrix Development

| Criterion | Weight | Indicators of Excellence | Common Deficiencies |
|:---|:---|:---|:---|
| **Subfunction coverage** | 20% | All function structure subfunctions represented; proper sequence | Missing subfunctions; wrong order |
| **Principle quantity** | 15% | 3-6 principles per subfunction; meaningful variety | Too few (<3) or too many (>8) without organization |
| **Principle quality** | 20% | Clear descriptions; informative sketches; physical basis explained | Words only; vague descriptions; no sketches |
| **Compatibility analysis** | 20% | Systematic verification; documented incompatibilities; valid combinations identified | Random selection; no compatibility check; undocumented assumptions |
| **Selection rigor** | 15% | Requirements-based filtering; budget check; documented rejections | Arbitrary selection; no documentation |
| **Combination documentation** | 10% | Clear working structure sketch; E-M-S flows shown; traceable to function structure | Incomplete sketch; missing flows |

### Defense-Specific Additional Criteria

| Criterion | Weight | Indicators of Excellence |
|:---|:---|:---|
| MIL-STD compatibility check | 10% | Environmental requirements mapped to principle selection |
| Supply chain assessment | 10% | Source identified for each principle; export control flagged |
| Vietnamese manufacturing fit | 10% | Local capability mapped; technology transfer path identified |

### Red Flags That Trigger Re-Work

1. ❌ No sketches in morphological matrix (verification impossible)
2. ❌ Combinations selected without compatibility analysis
3. ❌ All "best" options combined without integration check
4. ❌ Missing subfunctions from function structure
5. ❌ No documentation of rejected combinations
6. ❌ Supply chain not considered for defense application

## 6. CONCEPT EVALUATION: VDI 2225 Application

### Evaluating Working Structure Combinations

After generating 3-5 working structure candidates through morphological analysis, use VDI 2225 to systematically select the best concept.

### Evaluation Criteria for Working Structures

| Criterion | Weight (%) | Description | Scoring Guide |
|:---|:---|:---|:---|
| **Function fulfillment** | 25% | How completely does combination fulfill overall function? | 4=All subfunctions optimal; 0=Critical gaps |
| **Compatibility quality** | 20% | How smoothly do principles integrate? | 4=Seamless E-M-S flow; 0=Major interfaces |
| **Technical risk** | 15% | Maturity and reliability of principles | 4=Proven technology; 0=Unproven concepts |
| **Realization effort** | 15% | Development complexity | 4=Direct implementation; 0=Extensive R&D |
| **Cost potential** | 15% | Expected production cost | 4=Low cost potential; 0=High cost expected |
| **Defense suitability** | 10% | Environmental/operational fit | 4=Fully MIL-STD compliant; 0=Unsuitable |

Key Feedback Loops:
R1 (Reinforcing): Good function structure → More principle options → 
                  Better combinations → Clearer working structure → 
                  Better requirements for next project → Better function structure

B1 (Balancing): Incompatibility detected → Reduce combinations →

## 12. TARGETED DRILLS

### Drill Set: Morphological Matrix & Working Structure Combination

#### Drill 1: Matrix Structure Recognition (Pattern Recognition)
**Difficulty:** ⭐⭐ | **Duration:** 15 min | **Focus:** Identifying proper matrix organization

**Instructions:** Evaluate the following partial morphological matrix for a Machine Gun Mount System. Identify what's wrong and how to fix it.

**Problem:**
```
| Subfunction | Solution 1 | Solution 2 | Solution 3 |
|:---|:---|:---|:---|
| Mount gun | Tripod | Vehicle pintle | Naval pedestal |
| Absorb recoil | (blank) | Spring buffer | Hydraulic |
| Aim weapon | Manual traverse | Electric drive | Manual crank |
| Store ammo | Box magazine | Belt fed from can | Drum |
| Track target | Optical sight | Thermal sight | No sight |
```

**Questions:**
1. What critical element is missing from all cells?
2. What organizational issue exists in the row sequence?
3. What's wrong with row 2?
4. What's problematic about "No sight" as a solution principle?

**Model Answer:**

1. **Missing sketches.** Every cell should have rough sketches, not just text. Text alone makes compatibility assessment nearly impossible.

2. **Sequence doesn't follow E-M-S logic.** Better order: Store ammo (material input) → Mount gun (structure) → Track target (signal) → Aim weapon (energy application) → Absorb recoil (energy dissipation). Current order mixes energy, material, and structural functions randomly.

3. **Row 2 has a blank cell.** Never leave cells blank—if no solution exists, document why. Possible addition: "Muzzle brake (gas redirection)" for column 1.

4. **"No sight" is not a working principle.** A working principle describes HOW to fulfill a function, not the absence of a solution. Replace with alternative like "Iron sights (mechanical reference)" or "Laser pointer (projected aiming)."

#### Drill 2: Compatibility Analysis (Application)
**Difficulty:** ⭐⭐⭐ | **Duration:** 25 min | **Focus:** Systematic compatibility verification

**Instructions:** For the RCWS 12.7mm system, analyze compatibility between these subfunctions:

**Subfunction A: Stabilize platform**
- A1: Passive gyro-stabilized cradle
- A2: Active servo-controlled gimbals
- A3: Weapon-isolated soft mount

**Subfunction B: Control aiming**
- B1: Direct wire joystick
- B2: Wireless remote console
- B3: Autonomous tracking AI

**Task:** Create a compatibility matrix showing which A-B combinations are compatible. Document the physical/geometrical reason for any incompatibility.

**Model Answer:**

| Stabilization ↓ / Control → | B1 Wired Joystick | B2 Wireless Remote | B3 Autonomous AI |
|:---|:---|:---|:---|
| **A1 Passive Gyro** | ✓ (simple integration) | ✓ (standard interface) | ⚠ Limited (gyro can't provide position feedback needed for AI) |
| **A2 Active Servo** | ✓ (servo takes commands) | ✓ (wireless to servo controller) | ✓ (ideal - servo feedback + AI commands) |
| **A3 Soft Mount** | ⚠ Limited (soft mount adds vibration to manual aim) | ⚠ Limited (same vibration issue) | ✗ (AI needs stable platform reference) |

**Key Insights:**
- A2 (Active Servo) is compatible with ALL control methods - most versatile
- A3 (Soft Mount) conflicts with precise aiming requirements - eliminates most combinations
- A1+B3 is technically possible but suboptimal - AI can't fully utilize passive stabilization

#### Drill 3: Selection Process (Evaluation)
**Difficulty:** ⭐⭐⭐ | **Duration:** 30 min | **Focus:** Requirements-based selection

**Scenario:** You've generated 5 working structure combinations for an AR-VR Weapon Simulator from your morphological matrix. Apply selection process given these constraints:

**Requirements (Demands):**
- D1: Latency <30ms for visual feedback
- D2: Supports 5.56mm rifle AND 9mm pistol configurations
- D3: Unit cost <$3,000 USD

**Requirements (Wishes):**
- W1: Recoil simulation
- W2: Wireless operation
- W3: Multiplayer capability

**Combinations:**

| ID | Visual | Tracking | Haptic | Cost Est. | Latency | Configurations |
|:---|:---|:---|:---|:---|:---|:---|
| C1 | VR headset | Inside-out | Vest vibration | $2,500 | 20ms | Rifle+Pistol |
| C2 | AR glasses | Marker-based | Electric recoil | $4,200 | 25ms | Rifle only |
| C3 | Projection | Optical | None | $1,800 | 15ms | Rifle+Pistol |
| C4 | VR headset | Lighthouse | Pneumatic recoil | $3,500 | 35ms | Rifle+Pistol |
| C5 | AR glasses | IMU-only | Vest vibration | $2,200 | 22ms | Rifle+Pistol |

**Task:** 
1. Apply demands filter - which combinations are eliminated? Why?
2. Rank remaining combinations by wish fulfillment
3. Select top 2 for concept development with documented rationale

**Model Answer:**

**Step 1: Demands Filter**

| Combination | D1 (<30ms) | D2 (Both configs) | D3 (<$3,000) | PASS? |
|:---|:---|:---|:---|:---|
| C1 | ✓ 20ms | ✓ | ✓ $2,500 | ✓ PASS |
| C2 | ✓ 25ms | ✗ Rifle only | ✗ $4,200 | ✗ FAIL (D2, D3) |
| C3 | ✓ 15ms | ✓ | ✓ $1,800 | ✓ PASS |
| C4 | ✗ 35ms | ✓ | ✗ $3,500 | ✗ FAIL (D1, D3) |
| C5 | ✓ 22ms | ✓ | ✓ $2,200 | ✓ PASS |

**Remaining after demands filter:** C1, C3, C5

**Step 2: Wish Fulfillment Ranking**

| Combination | W1 Recoil | W2 Wireless | W3 Multiplayer | Wish Score |
|:---|:---|:---|:---|:---|
| C1 | ⚠ Partial (vest) | ✓ VR capable | ✓ VR native | 2.5/3 |
| C3 | ✗ None | ✗ Wired projection | ⚠ Possible | 0.5/3 |
| C5 | ⚠ Partial (vest) | ✓ AR capable | ⚠ Possible | 2/3 |

**Step 3: Selection**

**Selected for concept development:**
1. **C1 (VR + Inside-out + Vest)** - Highest wish score, all demands met comfortably, established VR ecosystem
2. **C5 (AR + IMU + Vest)** - Lower cost, AR offers see-through advantage for training environment awareness

**Rejected with rationale:**
- C2: Failed both D2 and D3 - cost and configuration limitations
- C3: Lowest wish fulfillment - no recoil simulation significantly limits training value
- C4: Failed D1 and D3 - latency and cost both exceed demands

                            │  (manual    │
                            │  reload)    │
                            └─────────────┘

FLOW LEGEND:
─────────── Energy flow (mechanical)
- - - - -  Signal flow (trigger/timer)
═════════  Material flow (pyrotechnic/smoke)

2. INTERFACE IDENTIFICATION
───────────────────────────────────────────────────────────────

Interface I1: Lever Release → Mechanical Timer
  - Type: Energy transfer (spring → escapement)
  - Challenge: Consistent trigger force required
  - Interface spec: Spring force 2-5N, travel 8mm

Interface I2: Mechanical Timer → Smoke Generator
  - Type: Signal (mechanical trigger)
  - Challenge: Reliable firing pin strike
  - Interface spec: Strike energy >0.5J, timing 3-5 sec

Interface I3: Smoke Generator → Reset Module
  - Type: Material (residue/spent cartridge)
  - Challenge: Complete burn before reset
  - Interface spec: Burn time <10 sec, cool-down <30 sec

3. TRACEABILITY STATEMENT
───────────────────────────────────────────────────────────────

Function Structure Reference: TG-FS-002 (dated 2025-12-15)

Subfunction Mapping:
  - "Accept user initiation" (FS 1.1) → Lever release principle
  - "Delay activation" (FS 1.2) → Mechanical timer principle
  - "Generate observable cue" (FS 2.1) → Smoke generator principle
  - "Enable reuse" (FS 3.1) → Manual reset principle

All four subfunctions from function structure are addressed.

4. KEY INTEGRATION CHALLENGES
───────────────────────────────────────────────────────────────

Challenge 1: Mechanical timer reliability
  - Risk: Escapement mechanism sensitive to orientation
  - Mitigation: Use gravity-independent design or digital backup

Challenge 2: Pyrotechnic safety
  - Risk: Premature ignition during handling
  - Mitigation: Multiple safety interlocks required

Challenge 3: Reset completeness verification
  - Risk: User doesn't properly reset before next use
  - Mitigation: Indicator flag shows armed/reset state

Challenge 4: Environmental durability
  - Risk: Vietnam tropical conditions affect timer/ignition
  - Mitigation: Sealed mechanism, MIL-STD-810 humidity spec

5. SELECTION RATIONALE
───────────────────────────────────────────────────────────────

This combination selected over alternatives because:

✓ Lever release (vs. button/pull-ring):
  - More realistic to actual grenade operation
  - Clear tactile feedback for training
  - Rejected button: Too different from real weapon

✓ Mechanical timer (vs. electronic):
  - No battery dependency in field conditions
  - Simpler maintenance at organizational level
  - Lower cost per unit
  - Rejected electronic: Battery logistics issue

✓ Smoke generation (vs. sound/light):
  - Visible at distance (100m+) for observer scoring
  - Works in daytime and low light
  - Provides area effect like real grenade
  - Rejected sound-only: Not visible to observers

✓ Manual reset (vs. automatic):
  - Simpler mechanism, lower failure rate
  - Training value in reload procedure
  - Lower cost
  - Rejected automatic: Complexity, cost, failure modes
