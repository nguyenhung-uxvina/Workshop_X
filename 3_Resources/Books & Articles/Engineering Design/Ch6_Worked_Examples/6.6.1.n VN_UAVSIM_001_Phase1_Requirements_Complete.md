## 1. PROBLEM STATEMENT (HOÀN THIỆN)

### 1.1 Điền vào bảng Problem Statement

| Aspect | Mô Tả Chi Tiết |
|--------|----------------|
| **Current State (Hiện trạng)** | Hiện tại việc huấn luyện phi công UAV trinh sát tại Việt Nam chủ yếu dựa vào: (1) Bay thực với UAV thật - chi phí cao ($500/giờ bay), rủi ro mất máy; (2) Mô phỏng đơn giản trên PC gaming - thiếu fidelity, không realistic; (3) Simulator nhập khẩu - đắt ($200K+), phụ thuộc nước ngoài, không có terrain Việt Nam. Thiếu hệ thống tích hợp VR + GCS thực cho huấn luyện chuyên nghiệp. |
| **Pain Points (Điểm đau)** | ① **Chi phí cao:** Mỗi giờ bay thực ~$500, cần 100h để đạt proficiency = $50,000/pilot; ② **Rủi ro mất UAV:** UAV trinh sát $50-200K, hư hỏng trong huấn luyện = thiệt hại lớn; ③ **Thiếu scenario đa dạng:** Không thể huấn luyện bad weather, emergency, night ops an toàn; ④ **Không có địa hình Việt Nam:** Simulator nước ngoài không có biên giới, biển đảo VN; ⑤ **Không đánh giá được objective:** Thiếu metrics, scoring, replay cho after-action review. |
| **Desired State (Mong muốn)** | Phi công được huấn luyện đầy đủ kỹ năng điều khiển UAV trinh sát với: (1) Chi phí giảm 80-90% so với bay thực; (2) An toàn 100% - không rủi ro mất UAV hoặc tai nạn; (3) Scenario phong phú bao gồm border patrol, SAR, night/weather; (4) Địa hình Việt Nam authentic; (5) Đánh giá khách quan với scoring và certification. |
| **Success Criteria** | ① **Giảm chi phí:** ≥80% so với huấn luyện bay thực ($50/h vs $500/h); ② **Zero accidents:** 0 tai nạn, 0 hư hỏng thiết bị trong huấn luyện; ③ **Skill transfer:** ≥85% kỹ năng chuyển giao sang UAV thực; ④ **Training time reduction:** Giảm 30% thời gian đạt proficiency; ⑤ **Customer satisfaction:** NPS ≥8/10 từ huấn luyện viên và học viên; ⑥ **Availability:** ≥95% uptime cho training schedule. |

## 2. INPUT FIELDS RESPONSES

### 2.1 Geometry (G.05)

**❓ Câu hỏi:** Instructor station riêng hay tích hợp?

**✅ Trả lời:** **INSTRUCTOR STATION RIÊNG (Separate)**

**Lý do:**
1. **Không gây phân tâm trainee:** Instructor có thể quan sát, điều chỉnh scenario mà không làm trainee bị distracted
2. **Inject events secretly:** Có thể inject failure, weather change mà trainee không biết trước
3. **Full visibility:** Instructor cần overview display khác với trainee POV
4. **Professional standard:** Tất cả military-grade simulators đều có separate instructor station

**Specification:**
| Item | Value |
|------|-------|
| Instructor station size | ≤1200 × 600 × 500 mm |
| Display | 24" main + 15" control touchscreen |
| Distance from trainee | 1.5-3m (line of sight) |
| Controls | Keyboard, mouse, touchscreen |

### 2.2 Kinematics (K.05)

**❓ Câu hỏi:** Loại UAV cần mô phỏng? Quadcopter/Hexacopter/Fixed-wing?

**✅ Trả lời:** **MULTIROTOR PRIMARY, VTOL HYBRID SECONDARY**

**Chi tiết:**

| Priority | Platform Type | Configurations | Use Case |
|----------|---------------|----------------|----------|
| **Primary (MUST)** | Quadcopter | 4-rotor, X/+ config | Short-range reconnaissance |
| **Primary (MUST)** | Hexacopter | 6-rotor, coaxial option | Medium-range surveillance, SAR |
| **Secondary (WISH)** | Octocopter | 8-rotor | Heavy payload, redundant |
| **Secondary (WISH)** | VTOL Hybrid | Tilt-rotor, tailsitter | Extended range patrol |
| **Out of Scope** | Fixed-wing | Traditional airplane | Not typical for Vietnamese reconnaissance use |
| **Out of Scope** | Combat UAV | Armed platforms | Riêng project khác |

**Lý do:**
1. **Vietnamese market reality:** Đa số UAV trinh sát hiện tại và tương lai là multirotor
2. **Mission profile match:** Border patrol, SAR phù hợp với multirotor hover capability
3. **GCS compatibility:** Các UAV Made in Vietnam (Viettel, GAET) đều là multirotor platform
4. **Expandability:** Có thể add fixed-wing model trong version 2.0

### 2.5 Operation (OP.10)

**❓ Câu hỏi:** Cần failure injection? (motor, GPS, comms)

**✅ Trả lời:** **CÓ - DEMAND (CRITICAL)**

**Failure Injection Matrix:**

| Category | Failure Type | Priority | Training Objective |
|----------|--------------|----------|-------------------|
| **Propulsion** | Single motor failure | D | Emergency landing, degraded flight |
| **Propulsion** | Multiple motor failure | W(H) | Autoland, emergency procedures |
| **Navigation** | GPS degradation | D | Dead reckoning, visual nav |
| **Navigation** | GPS loss | D | Return to last known, manual nav |
| **Navigation** | Compass drift | W(M) | Recognize and compensate |
| **Communication** | Datalink degradation | D | Reduced video quality |
| **Communication** | Datalink loss | D | Lost link procedures, RTH |
| **Power** | Battery warning | D | Mission abort decision |
| **Power** | Battery critical | D | Emergency landing |
| **Sensor** | Camera failure | W(H) | Alternative sensors |
| **Sensor** | IR failure | W(M) | Day camera fallback |

**Lý do:**
1. **Emergency preparedness:** 70% of UAV accidents involve equipment failure + pilot error
2. **Decision-making training:** Phi công cần practice "GO/NO-GO" decisions
3. **Procedure validation:** Validate emergency procedures in safe environment
4. **Confidence building:** Pilots who've handled simulated failures perform better in real emergencies
5. **MIL-STD-882E compliance:** Safety training requires failure scenarios

## 5. I ↔ C INDEPENDENCE REQUIREMENTS (CRITICAL)

### 5.1 Core Independence Requirement

Dựa trên Conceptual Design Analysis, hệ thống PHẢI đạt **I ↔ C Independence** (Immersion ↔ Control Fidelity Independence):

| Requirement | Specification | Rationale |
|-------------|---------------|-----------|
| Control latency | ≤10 ms CONSTANT | Must not vary with visual load |
| Visual frame rate | ≥90 Hz | VR minimum for comfort |
| Motion-to-photon | ≤20 ms | Motion sickness threshold |
| **Independence test** | **∂(Control_latency)/∂(Visual_complexity) ≈ 0** | **CRITICAL** |

### 5.2 Architecture Requirement

Hệ thống PHẢI sử dụng **Parallel Processing Pipeline Architecture**:

```
CONTROL PIPELINE (Real-time, Deterministic)
├── Input sampling: 1ms
├── Flight model: 5ms  
├── State output: 2ms
└── TOTAL: 8ms GUARANTEED (separate thread, high priority)

        ↓ Triple-buffered async state transfer

RENDER PIPELINE (Best effort, High quality)
├── State read: 1ms
├── Scene update: 3ms
├── GPU render: 6ms
├── VR display: 1ms
└── TOTAL: 11ms @ 90 Hz (separate thread)
```

### 5.3 Verification Requirements

| Test Case | Expected Result | Pass Criteria |
|-----------|-----------------|---------------|
| Standard terrain, measure control latency | ~8ms | Baseline |
| High-detail terrain (10x objects) | Control latency ~8ms | ≤10% variation |
| Weather effects ON | Control latency ~8ms | ≤10% variation |
| VR OFF (monitors only) | Control latency ~8ms | ≤10% variation |
| **Correlation coefficient** | r ≈ 0 | **I and C independent** |
