## EXECUTIVE SUMMARY

This document applies the complete Pahl & Beitz Section 6.6 eight-step conceptual design methodology to the **Small Arms Simulator (SAS)** - a high-fidelity weapon training system for INDIVIDUAL shooter proficiency development using rifles, pistols, and machine guns without live ammunition.

### Critical Distinction: SAS vs. Naval Weapon Simulator (NWS)

| Aspect | NWS (Previous Analysis) | SAS (This Analysis) |
|--------|-------------------------|---------------------|
| **Operator** | Crew team (2-4 members) | Individual shooter |
| **Weapon Type** | Ship-mounted systems (AK-630, AK-176) | Handheld small arms (rifle, pistol, MG) |
| **Environment** | Ship motion (6-DOF) | Shooter movement (tactical scenarios) |
| **Training Focus** | Crew coordination + procedures | Individual marksmanship + tactical judgment |
| **Scenario Complexity** | Multi-sensor (radar+optical+fire control) | Visual targets + judgment scenarios |
| **Physical Platform** | Fixed station with motion platform | Portable/deployable weapon replicas |
| **Independence Variable** | F ↔ R (Fidelity-Responsiveness) | F ↔ L (Fidelity-Latency) |

### Key Design Challenge: The F ↔ L Independence Problem

For effective marksmanship training:
- **Fidelity (F)**: Weapon must FEEL identical to real firearm (recoil impulse, trigger pull, cycling, weight, balance, malfunctions)
- **Latency (L)**: System must RESPOND within <15ms (trigger pull → recoil → shot registration → feedback)

**Traditional coupling**: Higher fidelity → more complex physics/actuation → higher latency
**SAS requirement**: BOTH high fidelity AND low latency → must achieve INDEPENDENCE

## PART 1: DESIGN CONTEXT AND REQUIREMENTS

### 1.1 System Definition

The **Small Arms Simulator (SAS)** is a high-fidelity weapon training system that:
- Replicates realistic weapon handling, firing, and malfunction clearance
- Provides immediate feedback on shot placement, technique, and decision-making
- Enables training scenarios from basic marksmanship to complex tactical judgment
- Operates without live ammunition (safe, cost-effective, unlimited repetitions)

### 1.2 Weapon Categories Supported

**Phase 1 (Initial Deployment):**
- **Rifles**: AK-47/AKM (7.62×39mm), M16/M4 (5.56×45mm)
- **Pistols**: Glock 17 (9mm), TT-33 (7.62×25mm)
- **Machine Guns**: RPK (7.62×39mm), PKM (7.62×54mmR) - hand-held training mode

**Phase 2 (Expansion):**
- Additional rifle variants (SVD, AK-74)
- Shotguns (12 gauge)
- Submachine guns (PP-19, Uzi variants)

### 1.3 Training Modalities

| Mode | Description | Key Requirements |
|------|-------------|------------------|
| **Dry-Fire Virtual** | CO₂/electric recoil + laser + projection | Recoil fidelity, shot registration |
| **CQB/Tactical** | Movement scenarios, shoot/no-shoot decisions | Ultra-short throw projection, judgment scoring |
| **Live-Fire Integration** | Real ammunition + projection targets + detection | Live-fire safe screens, ±5mm shot accuracy |
| **Malfunction Drills** | Instructor-controlled failures | HIL control over bolt/slide, Type 1/2/3 malfunctions |

### 1.4 Operational Environment

- **Indoor Facilities**: Controlled ranges, training centers, CQB houses
- **Field Deployment**: Mobile training units, field exercises (ruggedized)
- **Environmental Range**: Temperature 0-45°C, humidity 10-90% RH

## PART 3: ABSTRACTION AND ESSENTIAL PROBLEM (Step 2)

### 3.1 Five-Step Abstraction Process

**Step 1: Eliminate Personal Preferences**
- Remove "should look like military training system" → Focus on FUNCTION
- Remove "instructor prefers touchscreen" → Focus on CAPABILITY

**Step 2: Transform Quantitative to Qualitative**
- "<15ms latency" → "imperceptible delay"
- "70% recoil magnitude" → "realistic kinetic feedback"
- "±5mm accuracy" → "precise shot registration"

**Step 3: Expand to Generally Valid**
- "AK-47 simulator" → "replicate any small arm's dynamic behavior"
- "CO₂ recoil" → "provide kinetic feedback through any suitable mechanism"

**Step 4: Remove Implied Solutions**
- "Laser hit detection" → "detect shot placement"
- "Projection display" → "present visual targets"

**Step 5: Formulate Essential Problem**

### 3.2 Essential Problem Statement

> **"Replicate the COMPLETE FIRING EXPERIENCE of handheld small arms—including weapon handling, trigger operation, recoil dynamics, mechanical cycling, and malfunction behavior—with sufficient FIDELITY to develop transferable muscle memory, while maintaining system LATENCY below the threshold of human perception (<15ms), achieving INDEPENDENT control of simulation FIDELITY and system LATENCY to enable effective individual marksmanship and tactical judgment training."**

### 3.3 The F ↔ L Independence Requirement

**Why Independence Matters:**

Traditional coupling pattern:
```
Higher Fidelity → More Complex Physics
                → More Computation
                → More Actuation Delay
                → Higher Latency
                → POOR TRAINING (muscle memory learns wrong timing)
```

**Required Independence:**
```
Change Fidelity (recoil force, trigger feel) → Latency UNCHANGED
Change Latency (faster processor) → Fidelity UNCHANGED
Both achievable SIMULTANEOUSLY
```

**Training Implication:**
- If latency >15ms: Shooter unconsciously adjusts timing → negative training transfer
- If fidelity low: Muscle memory doesn't match real weapon → skill gaps
- BOTH must be achieved → requires architectural independence

### 3.4 Physics Parameters

**Weapon Dynamics (Design Inputs):**

| Parameter | AK-47 | M4/M16 | Glock 17 | PKM |
|-----------|-------|--------|----------|-----|
| Weight (loaded) | 3.8 kg | 3.4 kg | 0.9 kg | 9.0 kg |
| Recoil impulse | ~7.5 N·s | ~4.5 N·s | ~3.5 N·s | ~12 N·s |
| Cycle rate (full-auto) | 600 rpm | 700-950 rpm | N/A | 650-750 rpm |
| Trigger pull | 2.0-2.5 kg | 2.5-3.5 kg | 2.5 kg | 3.0-4.0 kg |
| Trigger travel | 6-8 mm | 5-7 mm | 12-15 mm | 8-10 mm |

**Latency Budget Breakdown:**

```
TOTAL BUDGET: <15ms end-to-end (trigger to feedback)

Component Allocation:
├─ Trigger sensor scan:      1 ms
├─ RTOS processing:          2 ms  
├─ Recoil command:           1 ms
├─ Actuator response:        5 ms  ← Critical path
├─ Shot detection:           2 ms
├─ Visual feedback:          4 ms
└─ TOTAL:                   15 ms  ✓

Parallel Processing Opportunity:
├─ Recoil path:    1+2+1+5 = 9ms
├─ Visual path:    1+2+4 = 7ms (parallel)
└─ EFFECTIVE:      9ms (limiting path) ✓✓
```

## PART 4: FUNCTION STRUCTURE VARIANTS (Step 3)

### 4.1 Overall Function

**Input:** Human actions (trigger pull, weapon handling, movement)
**Output:** Training effect (muscle memory, technique improvement, judgment development)
**Transformation:** Convert human inputs → realistic weapon response → performance feedback → skill transfer

### 4.2 Function Structure Variant Analysis

#### Variant 1: Centralized Processing Architecture

```
┌─────────────────────────────────────────────────────────────┐
│                    CENTRALIZED SERVER                        │
│  ┌─────────────────────────────────────────────────────┐   │
│  │            CENTRAL PROCESSING UNIT                   │   │
│  │  • All sensor processing                            │   │
│  │  • All physics calculations                         │   │
│  │  • All actuator commands                            │   │
│  │  • All visual rendering                             │   │
│  └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
           ↑                    ↓
    [All Sensors]        [All Actuators + Display]
           ↑                    ↓
      [WEAPON]             [FEEDBACK]
```

**Analysis:**
- All processing in single computer
- Single point of failure
- F and L STRONGLY COUPLED (more fidelity = more computation = more latency)
- Cannot guarantee <15ms under all conditions
- **VERDICT: REJECTED** - Coupling prevents F-L independence

#### Variant 2: Distributed HIL Architecture (Hardware-in-the-Loop)

```
┌──────────────────────── WEAPON LAYER ────────────────────────┐
│  ┌─────────────────┐    ┌─────────────────┐                 │
│  │  WEAPON UNIT    │    │  LOCAL RTOS     │                 │
│  │  • Real housing │◄──►│  • <2ms scan    │                 │
│  │  • Sensors      │    │  • <3ms process │                 │
│  │  • Actuators    │    │  • Recoil cmd   │                 │
│  └─────────────────┘    └─────────────────┘                 │
│         LOCAL LATENCY: <8ms (trigger to recoil) ✓           │
│         LOCAL FIDELITY: Real hardware + dynamics ✓          │
└─────────────────────────────────────────────────────────────┘
                              ↕ EtherCAT (real-time)
┌──────────────────────── SCENARIO LAYER ─────────────────────┐
│  ┌─────────────────┐    ┌─────────────────┐                 │
│  │ SCENARIO SERVER │    │  IMAGE GENERATOR│                 │
│  │  • Target logic │    │  • 3D rendering │                 │
│  │  • Scoring      │    │  • Effects      │                 │
│  │  • Recording    │    │  • Environment  │                 │
│  └─────────────────┘    └─────────────────┘                 │
│         SCENARIO LATENCY: <30ms (scenario to display) ✓     │
└─────────────────────────────────────────────────────────────┘
                              ↕
┌──────────────────────── INSTRUCTOR LAYER ───────────────────┐
│  ┌─────────────────────────────────────────┐               │
│  │     INSTRUCTOR OPERATION STATION        │               │
│  │  • Scenario control                     │               │
│  │  • Malfunction injection                │               │
│  │  • Performance monitoring               │               │
│  │  • Recording/AAR                        │               │
│  └─────────────────────────────────────────┘               │
└─────────────────────────────────────────────────────────────┘

F-L INDEPENDENCE VERIFICATION:
├─ Fidelity: Determined by WEAPON LAYER (hardware + dynamics tables)
├─ Latency: Determined by LOCAL RTOS (dedicated, deterministic)
├─ Change F: Update weapon hardware/tables → L unchanged ✓
├─ Change L: Faster processor → F unchanged ✓
└─ INDEPENDENT ✓
```

**Analysis:**
- Weapon-level processing handles time-critical fidelity
- RTOS guarantees deterministic <15ms
- Scenario processing runs in parallel (non-blocking)
- TRUE F-L independence through architectural separation
- **VERDICT: SELECTED** - Best balance of fidelity, latency, scalability

#### Variant 3: Pure Pneumatic/Mechanical System

```
┌─────────────────────────────────────────────────────────────┐
│                  PNEUMATIC WEAPON UNIT                       │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐  │
│  │   Trigger    │───►│  Mechanical  │───►│   CO₂/Air    │  │
│  │   Linkage    │    │   Valve      │    │   Actuator   │  │
│  └──────────────┘    └──────────────┘    └──────────────┘  │
│                                                             │
│  + Extremely fast response (<3ms)                           │
│  + Very high fidelity (real mechanical feel)                │
│  - No malfunction simulation (pure mechanical)              │
│  - Limited tunability (fixed force profile)                 │
│  - Gas supply logistics                                     │
└─────────────────────────────────────────────────────────────┘
```

**Analysis:**
- Fastest possible response (purely mechanical)
- Highest "feel" fidelity (real mechanism)
- But NO electronic control for malfunctions
- Cannot implement instructor-controlled failures
- **VERDICT: PARTIAL** - Good for recoil, needs electronic augmentation

#### Variant 4: VR-Only Simulation

```
┌─────────────────────────────────────────────────────────────┐
│                    VR SIMULATION SYSTEM                      │
│                                                              │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐  │
│  │  VR Headset  │    │  Hand        │    │  Haptic      │  │
│  │  (Visual)    │    │  Controllers │    │  Vest        │  │
│  └──────────────┘    └──────────────┘    └──────────────┘  │
│                                                              │
│  + Low cost ($2-5K)                                         │
│  + Highly portable                                          │
│  + Unlimited scenarios                                      │
│  - NO physical weapon (no weight, no real trigger)          │
│  - Motion sickness risk                                     │
│  - Minimal skill transfer for malfunction clearance         │
│  - NO recoil (haptic vest insufficient)                     │
└─────────────────────────────────────────────────────────────┘
```

**Analysis:**
- Lowest cost
- Most portable
- But fundamentally lacks physical weapon fidelity
- Cannot train realistic weapon handling
- **VERDICT: SUPPLEMENTARY** - Familiarization only, not proficiency

### 4.3 Function Structure Selection

| Criterion | Variant 1 | Variant 2 | Variant 3 | Variant 4 |
|-----------|-----------|-----------|-----------|-----------|
| F-L Independence | ✗ Coupled | ✓ Independent | ✓ Independent | N/A |
| Weapon Fidelity | Medium | High | Very High | Very Low |
| Malfunction Control | Limited | Full | None | Full (virtual) |
| Latency Guarantee | No | Yes (<15ms) | Yes (<5ms) | Yes |
| Cost | Medium | Medium-High | Medium | Low |
| Scalability | Poor | Good | Good | Excellent |

**Selected Architecture: Variant 2 - Distributed HIL**
- Achieves TRUE F-L independence
- Meets all DEMAND requirements
- Supports full malfunction simulation
- Provides deterministic latency guarantee
