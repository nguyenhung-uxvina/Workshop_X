## 2. STATE CATALOG

### 2.1 Primary States (top-level)

```
State ID  │ Name              │ Description
──────────┼───────────────────┼────────────────────────────────────────────
S0        │ OFFLINE           │ System powered off / not initialized
S1        │ INITIALIZING      │ Boot sequence, agent health checks
S2        │ STANDBY           │ Ready, awaiting session start command
S3        │ SESSION_ACTIVE    │ Training session running — composite state (§2.2)
S4        │ HITL_PAUSE        │ Awaiting human decision (read-only system)
S5        │ FAULT             │ Irrecoverable error — human intervention required
S6        │ MAINTENANCE       │ Diagnostic / calibration mode
S7        │ SHUTDOWN          │ Graceful shutdown sequence
```

### 2.2 SESSION_ACTIVE — Composite State (Sub-states)

```
S3 — SESSION_ACTIVE contains:

  S3.1  │ AWAITING_SHOT      │ Sensors armed, waiting for shot event
  S3.2  │ ACOUSTIC_DETECT    │ VN-LOMAH processing gunshot signature
  S3.3  │ VISION_SCORE       │ VN-CAM processing impact frame
  S3.4  │ FUSION_CORRELATE   │ FUSION ENGINE correlating acoustic + visual data
  S3.5  │ SCORING_COMPLETE   │ Shot scored, result buffered in session log
  S3.6  │ QUALIFICATION_EVAL │ Checking if unit qualification threshold met
  S3.7  │ CERT_GENERATION    │ Generating qualification certificate (VN-TRN)
```

### 2.3 FAULT — Composite State (Sub-states)

```
S5 — FAULT contains:

  S5.1  │ SENSOR_FAULT       │ LOMAH or CAM below confidence threshold (3 retries exhausted)
  S5.2  │ FUSION_FAULT       │ Acoustic / visual counts persistently mismatched
  S5.3  │ SAFETY_FAULT       │ Safety fan violation detected — HARD HALT
  S5.4  │ COMMS_FAULT        │ Agent communication timeout
  S5.5  │ DATA_FAULT         │ Session log corruption or write failure
```

## 5. GUARD CONDITIONS — FORMAL DEFINITIONS

```python
# All guards are pure boolean functions evaluated at transition time.
# CORTEX evaluates guards atomically — no side effects during guard check.

def power_ok() -> bool:
    return all(v >= VOLTAGE_MIN for v in read_power_rails())

def agents_ok() -> bool:
    return all(agent.health_check() == "OK" for agent in [LOMAH, CAM, TRN, FUSION])

def rso_cleared() -> bool:
    return rso_panel.is_range_clear() and rso_panel.is_safety_armed()

def confidence_ok(agent_output) -> bool:
    return agent_output.confidence >= CONFIDENCE_THRESHOLD  # 0.85

def retry_exhausted() -> bool:
    return retry_count >= MAX_RETRY  # 3

def count_match() -> bool:
    return abs(lomah_count - cam_count) == 0

def count_delta_ok() -> bool:
    return abs(lomah_count - cam_count) <= 1

def rounds_remain() -> bool:
    return session_log.rounds_fired < session_config.rounds_total

def qual_threshold_met() -> bool:
    return session_log.score_pct >= session_config.qualification_pct

def rso_signed_off() -> bool:
    return rso_panel.incident_acknowledged and rso_panel.sign_off_received

def already_running() -> bool:
    return system_state == "STANDBY"

# Constants
CONFIDENCE_THRESHOLD = 0.85
MAX_RETRY = 3
SHOT_TIMEOUT_SEC = 5.0
```

## 7. HITL INTERRUPT MECHANISM

### 7.1 How HITL Works at Any State

HITL is not a polling mechanism — it is an **interrupt**. Any HITL event (§3.3) from RSO takes priority over all active processing. The mechanism:

```
HITL INTERRUPT PROTOCOL:
═════════════════════════════════════════════════════════════

1. HITL event received (E_RSO_HALT, E_RO_OVERRIDE, etc.)
         │
         ▼
2. CORTEX immediately suspends active agent tasks
   - Sends "SUSPEND" command to all active agents
   - Agents complete their current atomic operation, then pause
   - CORTEX snapshots current state to HITL_CONTEXT buffer
         │
         ▼
3. CORTEX transitions to S4 (HITL_PAUSE)
   - All agent outputs buffered (not discarded)
   - Session log paused (not closed)
   - HITL_CONTEXT preserved: {prior_state, pending_decision, agent_snapshots}
         │
         ▼
4. Human reviews situation (read-only access to all agent data)
         │
         ├── E_RO_APPROVE → resume_from_hitl(HITL_CONTEXT)
         │    CORTEX restores prior state and continues
         │
         └── E_RO_REJECT → discard_shot(); return to S3.1
              CORTEX discards current shot, clears buffers,
              returns to AWAITING_SHOT with count adjusted

RSO_HALT EXCEPTION (does NOT go through S4):
  E_RSO_HALT → IMMEDIATE transition to S5.3
  No buffering, no approval process — hard stop
  Requires E_RSO_RESUME with rso_signed_off guard to exit
```

### 7.2 HITL Decision Matrix

```
HITL Trigger                    │ Who Notified │ Decision Required
────────────────────────────────┼──────────────┼─────────────────────────────────────
Low acoustic confidence         │ RO           │ Accept AI score OR manual recount
Low visual confidence           │ RO           │ Accept AI score OR manual inspect
CAM: no detection after retries │ RO           │ Score as miss OR manual inspect
Count delta = 1                 │ RO           │ Accept lower count OR manual recount
Qualification threshold not met │ RO + KN      │ Additional rounds OR end session
Safety fan violation            │ RSO (HARD)   │ Incident report + signed clearance
Large count mismatch (delta > 1)│ RSO + KN     │ Investigate + full manual recount
```

## 8. ERROR RECOVERY FSM

```
FAULT STATE RECOVERY PATHS:
══════════════════════════════════════════════════════════════════

S5.1 (SENSOR_FAULT)
  Cause:   LOMAH retries exhausted
  Path:    RO selects → manual scoring mode
  Action:  disable_lomah(); switch_to_manual_mode()
  Resume:  S3.1 with MANUAL_SCORING flag set

S5.2 (FUSION_FAULT)
  Cause:   Persistent acoustic/visual mismatch (delta > 1)
  Path:    KN investigates → field calibration or restart
  Action:  log_fusion_fault(); dump_sensor_data(); halt_session()
  Resume:  After calibration: S1 (full reinit)
           After investigation: S3.1 with PENDING_RECOUNT flag

S5.3 (SAFETY_FAULT)
  Cause:   Safety fan violation OR RSO hard halt
  Path:    MANDATORY — RSO incident report + sign-off
  Action:  halt_all_agents(); seal_session_log(); alert_all()
  Resume:  ONLY via E_RSO_RESUME with rso_signed_off guard
           Resume target: S2 (STANDBY) — session cannot resume

S5.4 (COMMS_FAULT)
  Cause:   Agent communication timeout
  Path:    Auto-retry 3x → if fails, KN manual intervention
  Action:  attempt_reconnect(); if_fail: log_fault(agent_id)
  Resume:  Reconnect success: return to [prior_state]
           Reconnect fail: S2 STANDBY, flag agent offline

S5.5 (DATA_FAULT)
  Cause:   Session log write failure (storage full, corruption)
  Path:    MANDATORY HITL — cannot score without audit trail
  Action:  suspend_session(); alert_kn(); attempt_backup_write()
  Resume:  Backup success: continue with backup storage
           Backup fail: end session, manual paper log required
```

## 10. SKILL 2 FORMALIZATION — WHAT THIS SPEC DEMONSTRATES

### From Conceptual Graph → Formal Machine

| Informal graph (prior)                     | Formal spec (this doc) |
|--------------------------------------------|------------------------|
| "Route to officer for manual scoring"      | HITL_PAUSE state + E_RO_APPROVE/REJECT events |
| "IMMEDIATE HALT"                           | S5.3 (SAFETY_FAULT) with hard RSO path |
| "IF confidence < 0.85"                     | `confidence_ok()` guard in §5, applied at S3.2 and S3.3 |
| "MAX_RETRY = 3"                            | `retry_exhausted()` guard + retry_count++ action |
| "Infinite loop prevention"                 | Explicit TIMEOUT event + FAULT transition |
| "Fallback = Manual scoring"               | S5.1 recovery path: `disable_lomah(); switch_to_manual_mode()` |

### What the Formal Spec Adds

1. **All states are named and numbered** — no undefined behavior, no ambiguous transitions
2. **Events are typed and sourced** — hardware vs. internal vs. HITL clearly separated
3. **Guards are code-ready** — §5 functions can be directly implemented in Python/C
4. **Timing constraints are quantified** — 100ms halt latency, 5s shot timeout are measurable
5. **Error recovery is deterministic** — each fault state has exactly one recovery path
6. **HITL is an interrupt, not a polling loop** — safety-correct design pattern
