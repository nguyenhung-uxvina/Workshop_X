## System Analysis: Your Skill Acquisition as a System

Before jumping to solutions, let's map the system:

```
INPUTS                    THROUGHPUTS                 OUTPUTS
─────                     ───────────                 ───────
• Time (2-4hr evenings)   • Mental models             • Agent orchestration ability
• Existing AI infra       • Practice quality          • Quality control intuition
• D-M-I-R framework       • Feedback loop speed       • Automation architecture skill
• Defense project context  • Pattern recognition       • Governance judgment
                          • Compound learning rate     • Judgment under ambiguity
```

### Key Feedback Loops Identified

**R1 (Reinforcing — Compound Learning):** Better agent management → more AI leverage → more project output → more complex problems → deeper skill development → even better agent management

**R2 (Reinforcing — Deploy to Learn):** Apply skill on real project → immediate feedback → pattern recognition → faster next application → more projects attempted

**B1 (Balancing — Cognitive Overload):** 5 skills simultaneously → attention fragmentation → shallow practice → slow progress → frustration → reduced practice

**B2 (Balancing — Perfectionism Trap):** Want to master before deploying → delay deployment → no feedback → no learning → want more study first

### The Binding Constraint

You already have the AI infrastructure, the systems thinking framework, and the defense project context. **The binding constraint is not knowledge — it's deliberate practice with compressed feedback loops.** You know *about* these skills. The gap is *performing* them under pressure until they become intuition.

## Naval's Revision: What the Article Gets Right and Wrong

### What it gets right:
- The 5-skill taxonomy is accurate and battle-tested
- "Agents handle the WHAT, humans own the WHY and SO WHAT" — this is the correct framing
- The Devin reality check is honest: agents crush boilerplate but fail on ambiguity
- Adaptability > syntax — learning how to learn is the meta-skill

### What it gets wrong (or leaves incomplete):

**1. It treats these as separate skills. They're not. They're one system.**

Agent management without critical reasoning is dangerous. Orchestration without governance is reckless. Process design without adaptability is brittle. These 5 skills are nodes in a single competency graph. Master the connections, not the nodes.

**2. It focuses on knowing, not doing.**

The article gives you the menu. It doesn't teach you to cook. Knowing that "structured delegation beats unguided LLM calls" is level 0. Doing it instinctively under production pressure is level 10. The gap between those two is where all the value lives.

**3. It doesn't address the learning system itself.**

How do you *actually* acquire these skills? The article assumes exposure equals competence. It doesn't. You need deliberate practice with tight feedback loops, not just conceptual understanding.

**4. It undervalues the meta-skill.**

"Adaptability and self-directed learning" is buried as one of four "broader skills." Wrong hierarchy. It's the skill that generates all other skills. In Meadows' terms, it's L2 — the paradigm that produces the goals, rules, and structure of everything else.

## The Self-Assessment Rubric

Score yourself 1-5 each Sunday. Be ruthless.

### Skill 1: AI Literacy & Agent Management

| Level | Description |
|-------|-------------|
| 1 | I use agents like search engines — ask question, get answer |
| 2 | I provide context and constraints but don't structure the delegation |
| 3 | I write structured agent parameters (task, context, constraints, tools, checkpoints) consistently |
| 4 | I anticipate agent failure modes and pre-design guardrails before delegation |
| 5 | I instinctively calibrate delegation complexity to agent capability and know exactly when to intervene |

### Skill 2: Multi-Agent Orchestration

| Level | Description |
|-------|-------------|
| 1 | I use one agent at a time for isolated tasks |
| 2 | I chain agents manually — output of one becomes input of next |
| 3 | I design explicit pipelines with defined handoff protocols and shared state |
| 4 | I build conditional logic — agents route differently based on intermediate results |
| 5 | I architect self-correcting multi-agent systems with automatic escalation to human judgment |

### Skill 3: Critical Reasoning & Quality Control

| Level | Description |
|-------|-------------|
| 1 | I accept agent output at face value if it "looks right" |
| 2 | I spot obvious errors (wrong facts, bad formatting) |
| 3 | I catch subtle logic errors, missing edge cases, and hidden assumptions |
| 4 | I evaluate agent reasoning chains, not just final outputs — I know *why* it went wrong |
| 5 | I predict where an agent will fail before I see the output, and design my review process accordingly |

### Skill 4: Process Automation Design

| Level | Description |
|-------|-------------|
| 1 | I automate whatever's easy without analyzing the full workflow |
| 2 | I map workflows before automating and identify manual vs. automated steps |
| 3 | I design HITL checkpoints at decision points and build fallback protocols |
| 4 | I architect automation graphs considering edge cases, API failures, and state machine recovery |
| 5 | I design self-healing automation systems that degrade gracefully and learn from failures |

### Skill 5: Conflict Mitigation & Ethical Governance

| Level | Description |
|-------|-------------|
| 1 | I don't think about governance — if the agent output looks good, I ship it |
| 2 | I check agent outputs against explicit rules and policies before shipping |
| 3 | I proactively identify where agent recommendations might conflict with policy, ethics, or common sense |
| 4 | I design governance frameworks that embed compliance checks into the agent pipeline itself |
| 5 | I make judgment calls under ambiguity where no rule clearly applies, balancing competing stakeholder interests |

## The 12-Week Mastery Sprint

### Phase 1: Foundation (Weeks 1-4) — "Wire the System"

**Goal:** Install feedback loops and mental models. Get the system running.

- **Week 1 — Spotlight: Agent Delegation.** Every Claude Code session becomes delegation practice. Write structured parameters for every task. Log what works and what doesn't.
- **Week 2 — Spotlight: Critical Reasoning.** After every agent output, spend 2 minutes finding what's wrong. Keep a "catches log." Celebrate finding errors.
- **Week 3 — Spotlight: Orchestration.** Design a multi-agent pipeline for one BB-01 deliverable. Map the agents, handoffs, checkpoints, and failure modes.
- **Week 4 — Spotlight: Process Design.** Map one complete workflow from your defense projects. Identify: what's automatable, where HITL goes, what happens when things break.

**Phase 1 Exit Criteria:** All skills at Level 2+. Micro-review habit installed. Weekly self-assessment habit installed.

### Phase 2: Integration (Weeks 5-8) — "Connect the Nodes"

**Goal:** Stop practicing skills in isolation. Start seeing the integrated system.

- **Week 5 — Integration Challenge:** Design and execute a complete agent-assisted deliverable that requires all 5 skills working together. Document where the skills connect.
- **Week 6 — Failure Analysis Week.** Deliberately push agents past their limits. Find breaking points. Document every failure mode and your human response.
- **Week 7 — Governance Stress Test.** Review past agent outputs through a governance lens. What would have gone wrong if you'd shipped without review? Build your governance intuition.
- **Week 8 — Speed Run.** Time yourself on a complete agent-assisted workflow. Then do it again faster. Then again. Build automaticity.

**Phase 2 Exit Criteria:** All skills at Level 3+. Integration moments happening naturally. Agent collaboration feels like second nature for routine tasks.

### Phase 3: Mastery (Weeks 9-12) — "Own the Edge Cases"

**Goal:** Handle ambiguity, novel situations, and high-stakes decisions with confidence.

- **Week 9 — Novel Problem Week.** Apply the skill stack to a problem you've never solved before. Observe how the skills transfer.
- **Week 10 — Teaching Week.** Teach one colleague how to delegate to agents effectively. Teaching reveals your gaps.
- **Week 11 — Architecture Week.** Design an autonomous overnight agent system for a defense deliverable. This is the integration final exam.
- **Week 12 — Reflection & Recalibration.** Full D-M-I-R cycle on the 12-week sprint. What worked? What was the actual binding constraint? Where's the next leverage point?

**Phase 3 Exit Criteria:** All skills at Level 4+. You can design, execute, review, and govern complex multi-agent workflows with minimal conscious effort.

## Quick Reference: Daily Practice Protocol

```
BEFORE SESSION (2 min):
  → Name today's spotlight skill
  → Set one specific practice intention

DURING SESSION (your normal 2-4 hours):
  → Work on real deliverables (deploy to learn)
  → After every agent output: 2-min micro-review
    • What did the agent get wrong?
    • What delegation error did I make?
    • What governance concern exists?

AFTER SESSION (5 min):
  → Log in Obsidian:
    • Skills practiced (count)
    • Best catch of the session
    • One thing I'd do differently
    • Integration moment (if any)

WEEKLY (Sunday, 15 min):
  → Self-assessment rubric (score 1-5 per skill)
  → Identify lowest skill → next week's spotlight
  → Review catch log → am I getting better?
```
