## 2. KEY FINDINGS

### 2.1 Realistic UAV Evasion Patterns ★★★

**DoD Group Classification (authoritative baseline):**

| Group | Weight | Max Speed | Max Altitude | Typical Airframe |
|-------|--------|-----------|--------------|-----------------|
| Group 1 | < 9.1 kg | < 190 km/h | < 370 m AGL | Multirotor, mini-FW |
| Group 2 | 9.5–25 kg | < 460 km/h | < 1,067 m AGL | Fixed-wing tactical |
| Group 3 | 25–600 kg | < 460 km/h | < 5,500 m | MALE-class UAVs |

**FPV Kamikaze profiles (Ukraine operational data, 2023–2026):**
- **Cruise phase:** 50–75 km/h, 200–400 m AGL — loitering, target search
- **Attack phase:** 150–300 km/h terminal dive — top-attack or side-attack depending on target type
- **Interceptor FPV:** 300–400 km/h top speed — dome-shaped, weighs < 2 kg
- **Payload:** Standard FPV = 1–2 kg. Upscaled ("Queen Hornet" class) = 7 kg+
- **Range:** 20 km standard via radio link; fiber-optic guided = line-of-sight only but jam-proof
- **Evasion approach:** Low-level NOE (nap-of-earth), high-speed, small RCS, approach from sun direction or terrain masking. From 2025, autonomous terminal guidance eliminates predictable radio-link geometry.
- **Swarm coordination (Ukraine observed):** Wave attacks, 4–8 FPVs per wave, staggered timing 30–90 seconds between units. Not true algorithmic swarms — currently human-coordinated.

**Fixed-wing loitering munition (Shahed-136 class):**
- Cruise: 180–200 km/h, 1,500 m over land / 2,000–2,500 m from sea
- Approach: straight-line GPS-guided, pop-up terminal maneuver (recent variants)
- Evasion: altitude variation, timing unpredictability, night ops, low IR signature
- Swarm: 50–100 unit salvos observed in Ukraine 2024

**Academic evasion model (arXiv 2409.15866 — MARL pursuit-evasion):** ★★★
- Evader prediction-enhanced network: predict pursuer positions N steps ahead → select trajectory maximizing separation
- Adaptive environment generator: randomizes obstacles and threat positions to prevent overfitting
- Three evasion states: **Collective flight** (formation), **Individual evasion** (break formation, maximize escape angle), **Local-following** (rejoin nearest ally after evade)
- Transition triggers: threat detection radius, angular closure rate threshold

### 2.2 USV Attack Profiles ★★★

**Houthi Toofan/Blowfish confirmed specifications (H.I. Sutton + Army Recognition):**

| Variant | Length | Speed | Warhead | Guidance | Profile |
|---------|--------|-------|---------|----------|---------|
| Toofan-1 | ~7 m | 35 knots (65 km/h) | 150 kg HE | GPS + video feed | V-hull planing, wave-cutting |
| Toofan-2 | Larger | ~30 knots | ~200 kg | GPS + mothership C2 | First observed type (2018) |
| Toofan-3 | Unknown | Unknown | Unknown | Unknown | Believed to be advanced variant |

**Attack approach pattern (observed operations):**
1. **Mothership phase:** USV towed to launch radius (>15 nm) by mothership
2. **Human pilot phase:** Human aboard or aboard skiff navigates to attack start line (~2–5 nm from target)
3. **Autonomous attack phase:** Pilot transfers to skiff, USV proceeds autonomously to target
4. **Terminal phase:** Straight high-speed approach at 35 knots OR zigzag/jinking to defeat Phalanx/CIWS tracking (observed in MV Tutor attack, June 2024). Detonation at waterline.
5. **Multi-vector swarm:** Coordinated air + surface attack — multiple USVs + UAVs simultaneously from different bearings to saturate defenses (observed Red Sea 2024)

**Key tactical characteristics:**
- Camouflage: disguised as fishing boat or skiff to defeat visual identification
- Attack bearing: approach from sun glare or coastal clutter to defeat radar/optical
- Jinking at terminal: ~3–5 degree heading changes at 2–4 second intervals (estimated from video analysis)
- Detonation point: waterline at engine compartment (most structurally vulnerable)

### 2.3 Swarm Coordination Algorithms ★★★

**From academic sources:**

1. **Boids algorithm (Reynolds 1987) — foundational:**
   - Separation: steer to avoid crowding
   - Alignment: steer toward average heading of neighbors
   - Cohesion: steer toward average position of neighbors
   - Extension for military: add **threat avoidance vector** and **target attraction vector** — weighted combination

2. **MARL-based swarm (arXiv 2409.15866):** ★★★
   - Each agent has partial observation (limited radius)
   - Shared reward: maximize territorial control / minimize interception rate
   - Policy: actor-critic with LSTM for temporal context
   - Achieves emergent flocking + evasion without explicit programming

3. **Bigraph-based swarm modeling (PMC 7830453):**
   - UAV swarm states modeled as bigraphical reactive systems
   - Formal verification possible — useful for C-UAS training scenarios (can certify behavior envelope)

4. **Harris swarm patent (US9488981B2):** ★★★
   - "Communication sphere" concept: each drone maintains connectivity with N nearest neighbors
   - Geometry: maintains inter-UAV spacing via PD controller on relative position
   - Reconfigurable: swarm can split → attack multiple targets → regroup

5. **Personality sharing (US10831197B2 — Qualcomm):**
   - Behavioral parameters (aggression, evasion threshold, formation spacing) encoded as "personality"
   - Parameters shared/averaged across swarm via gossip protocol
   - Enables emergent group identity without centralized control — resilient to leader kill

## 3. RECOMMENDED BEHAVIOR TREE ARCHITECTURE

### 3.1 Design Principles (from arXiv 1405.7944 + 2005.05842)

- **Reactive, modular, tick-based** — every tree node returns SUCCESS / FAILURE / RUNNING
- **Blackboard architecture** — shared sensor data (own position, target position, threat detections, fuel/battery) written by sensors, read by all nodes
- **Priority ordering** — safety > survival > mission. High-priority subtrees checked first each tick
- **Parameterized leaf nodes** — same tree architecture, different parameters per UAV type

### 4.2 UAV Physics Model (Groups 1–3, real-time)

**Multirotor (U1, U3) — simplified 6DOF:**
```
Force_total = Thrust_vector - Drag - Gravity
Thrust = sum(rotor_RPM^2 * k_T) per rotor
Drag = 0.5 * rho * Cd * A * v^2 (simplified sphere drag)
Max angular rate: ±600 deg/s (FPV racing)
Typical Cd: 0.3–0.5 for compact FPV

For training simulation: use Unity Rigidbody.AddForce()
Set drag coefficient via Rigidbody.drag = 0.1–0.3
Override rotation with quaternion slerp for responsive feel
```

**Fixed-wing (U2, U4) — point-mass flight model:**
```
L = 0.5 * rho * v^2 * S * CL(alpha)
D = 0.5 * rho * v^2 * S * CD(CL)
Thrust = engine constant (simplified)
Bank-to-turn: roll → coordinated turn without sideslip
Min speed (stall): ~0.8 * V_stall
For training: use ProBuilt Aircraft Physics asset OR custom Rigidbody with lift equation
```

**IEEE model reference (Xplore 7502599):** 6DOF first-principles with propeller slipstream, runs real-time with pilot-in-loop. Applicable to Group 2–3 simulation. Key finding: aerodynamic coefficients can be estimated from geometry alone (no wind tunnel required) with < 15% error.

### 4.3 USV Hydrodynamic Model (simplified for real-time)

**Fossen simplified model (arXiv 2303.13064):**
```
Surge: m * u_dot = X_u * u + X_prop * n^2  (n = propeller RPM)
Sway:  m * v_dot = Y_v * v + Y_r * r
Yaw:   I_z * r_dot = N_v * v + N_r * r

Hydrodynamic coefficients estimated via:
  X_u = -0.5 * rho * Cd_surge * A_frontal * v_max
  Y_v = -0.5 * rho * Cd_sway * A_lateral * v_max
  (least-squares fit from pool trials)
```

**Unity implementation:**
```csharp
// Apply hydrodynamic forces each FixedUpdate
void FixedUpdate() {
    float u = localVelocity.z; // surge
    float v = localVelocity.x; // sway
    float r = angularVelocity.y; // yaw rate

    float F_surge = Xu * u + thrust;
    float F_sway = Yv * v + Yr * r;
    float M_yaw = Nv * v + Nr * r + rudderMoment;

    rb.AddRelativeForce(new Vector3(F_sway, 0, F_surge));
    rb.AddRelativeTorque(new Vector3(0, M_yaw, 0));
}
```

**Wave response (simplified):** Add sinusoidal vertical displacement based on SeaState (Beaufort). SeaState 3: amplitude ±0.5 m, period 4–6 s. Use Perlin noise for irregular waves.

## 5. TRAINING TRANSFER EVIDENCE

### 5.1 AI-Driven vs Scripted Target Behavior

**Finding 1 — Psychological fidelity > physical fidelity ★★★**
Source: PubMed meta-analysis (35815520), RAND RR2250

The critical finding from training transfer research: **medium-fidelity simulators outperform high-fidelity simulators for skill transfer** when the training population has low prior skill. What matters is **psychological fidelity** — does the simulation prompt the same cognitive, behavioral, and stress responses as the real threat?

Implication: An AI-driven target that behaves *unpredictably* (like a real threat) provides higher psychological fidelity than a scripted target even if the physics are simplified.

**Finding 2 — Scripted NPCs are explicitly insufficient for modern drone threats ★★★**
Source: RAND/IJRASET Generative AI for Military Simulations + Autonomy Global

Direct quote (paraphrased from sources): *"Scripted NPCs have predictable behaviors and are not able to realistically represent emergent threats, complex environments, and roles. AI-controlled adversaries can mimic the dynamic and random nature of real-life combat."*

US Army Synthetic Training Environment (STE) explicitly moved away from scripted computer-generated forces (CGFs) toward adaptive AI behavior for exactly this reason.

**Finding 3 — AI-driven training systems with quantified improvement ★★**
Source: PDW SIM case data (B-tier — treat as indicative only)

PDW SIM sUAS tactical simulator reports: **50% reduction in training time, 88% cost reduction** vs live-fly training. While these numbers come from a vendor (treat cautiously), the direction is confirmed by multiple independent sources.

Israel IDF: AI-generated threat scenarios incorporating evolving FPV attack profiles observed in Ukraine contributed to interception improvement (Breaking Defense, 2025) — no percentage cited.

**Finding 4 — RAND confirms adaptive simulation value for RL training ★★★**
Source: RAND RRA1722-6

RAND developed a software harness enabling reinforcement learning in constructive simulations without additional coding. Key finding: **RL-trained agents beat scripted agents in C2 games**. Applied to training: operators trained against RL-adaptive targets develop more generalizable skills than operators trained against fixed scripts.

**Finding 5 — Transfer: near vs far ★★★**
The three transfer types (self, near, far) all contribute to training effectiveness. For C-UAS:
- **Self-transfer:** practice same threat type → procedural automation
- **Near-transfer:** similar-but-not-identical threat behavior (e.g., FPV approach angle varies ±30°)
- **Far-transfer:** novel threat behavior → requires adaptive AI, not scripted

**Conclusion:** AI behavior trees with randomized parameters and adaptive evasion significantly outperform scripted targets for C-UAS operator training, particularly for **far transfer** — the ability to respond to novel threats not seen in training.

### 5.2 Minimum Viable Behavioral Fidelity for Training Transfer

Based on cross-source synthesis:

| Behavior Dimension | Minimum for Training Transfer | Why |
|-------------------|------------------------------|-----|
| Speed variability | ±20% around type nominal | Operators train speed estimation |
| Approach angle randomization | ±45° from direct bearing | Prevents bearing-lock habituation |
| Altitude profile randomization | ±30% around type nominal | Trains 3D tracking |
| Terminal phase decision branching | ≥ 2 options (AI-selected) | Prevents pattern memorization |
| Swarm timing desync | ±5–15 seconds between units | Saturates sensor attention |
| Evasion response latency | 0.5–2 seconds after threat detection | Realistic sensor + reaction model |
