# VN-12.7MM-SIM — Product Family Orchestration Design

## S2 Pattern 4: Parallel Pipeline with Shared Resources

---

## Section 0: Procurement Narrative

The VN-12.7MM-SIM product family delivers a complete 12.7mm naval gunnery training ecosystem — from mobile pre-training (tablet app) through full-fidelity fixed simulators to AI-coached adaptive training. Four products share a common software core (ballistic model, scenario engine, scoring algorithm), enabling rapid variant development and cumulative data value across the Vietnamese Navy training fleet.

Workshop X orchestrates this product family using a structured coordination framework that ensures:
- No product starts on unvalidated foundations (dependency gates)
- Shared resources (developer, fabrication, engineering time) are allocated by priority, not by urgency
- Changes to shared software propagate systematically, not silently
- The fastest-revenue product (tablet app, 4 months) funds development of the core platform (12 months)

This document defines the coordination architecture. Individual product design follows the standard Pahl & Beitz Phase 0-4 pipeline.

## Section 1: Design Principles

### Principle 1: Meta-Pattern Coordination

Pattern 4 does not replace Pattern 3 — it coordinates multiple Pattern 3 instances. Each product runs its own Workflow Orchestration (Pattern 3) through design phases. Pattern 4 adds the layer that decides WHICH product gets work, WHEN dependencies are met, and HOW shared resources are allocated.

```
Pattern 4 (Coordination Layer)
  ├── I-01 → Pattern 3 instance (Phase 0→1→2→3→4)
  ├── I-09 → Pattern 3 instance (Phase 0→1→2→3→4)
  ├── I-02 → Pattern 3 instance (depends on I-01.Phase3.ACCEPTED)
  └── I-08 → Pattern 3 instance (depends on I-01.Phase3.ACCEPTED + IRONMESH.ready)
```

### Principle 2: Escalate, Don't Retry

Coordination errors are structural, not transient. When the system detects a resource conflict, dependency gap, or allocation violation, the correct response is to escalate to human judgment — not retry the same logic. This distinguishes Pattern 4 from Pattern 1 (Pipeline), where retry fixes transient errors.

### Principle 3: State is the Single Source of Truth

Every coordination decision is based on file state, not session memory or inference. A-DEPEND checks state files, not "it should be done by now." A-SCHEDULE reads allocation trackers, not estimated effort. If the file says BLOCKED, the product is BLOCKED — regardless of what the Master thinks.

## Section 2: Agent Architecture

### Master Agent

```
MASTER: Product Family Coordinator (PFC)
  Domain:    Cross-product scheduling, dependency enforcement, resource arbitration
  State:     Externalized to files (reads at session open, writes at session close)
  Scope:     Decides WHICH product gets work THIS session
  Cannot:    Execute design work directly — delegates to per-product Pattern 3 instance
  Cannot:    Approve cross-product gates — presents to KN, waits indefinitely
  Cannot:    Override 25h/week cap or 3h buffer — hard constraint, no exception
```

### Coordination Sub-Agents (Pattern 4 Layer)

| Agent | Domain | Steps | Scope Boundary | What It CANNOT Do |
|-------|--------|-------|----------------|-------------------|
| **A-SCHEDULE** | Resource allocation + conflict detection | S1, S2, S6, S10 | Computes allocation proposals, detects conflicts, enforces 25h cap | Cannot approve allocation — proposes only. Cannot override buffer. |
| **A-DEPEND** | Dependency resolution + cross-product gates | S3, S8 | Checks product state files against dependency map. Reports blocked/ready. | Cannot declare a product ready if dependency file shows incomplete. Cannot approve cross-product gates (0% automated). |
| **A-SYNC** | Shared artifact propagation | S5 | Detects SW core changes, generates propagation checklist, tracks versions | Cannot auto-apply changes to downstream products. Flags for review. |
| **A-TRACK** | Progress dashboard + timeline | S4, S9 | Reads all product state files, generates family dashboard, flags slips | Cannot modify product state. Read-only across all products. |

### Per-Product Design Agents (Pattern 3 Instances)

Each product gets its own Pattern 3 Workflow Orchestration with shared stateless agents:

```
I-01 (Standard Fixed Trainer) ─── Pattern 3 ─── Phase 0 DONE → 1 → 2 → 3 → 4
I-09 (Tablet App) ─────────────── Pattern 3 ─── Phase 0 → 1 → 2 → 3 → 4
I-02 (Containerized) ──────────── Pattern 3 ─── BLOCKED until I-01.Phase3.ACCEPTED
I-08 (AI-Coached) ─────────────── Pattern 3 ─── BLOCKED until I-01.Phase3.ACCEPTED + IRONMESH.ready

Shared agent pool: A-ODI, A-REQ, A-CONCEPT, A-EMBODY, A-DETAIL, A-QC
(Stateless — same agents operate on different product state files)
```

## Section 3: Process Graph — Task() Delegation

### Session-Opening Protocol (MANDATORY)

```
Master reads coordination state:
  1. Read family_state.md         → all product phases + blocked/active status
  2. Read allocation_tracker.md   → hours remaining this week
  3. Read dependency_map.md       → which products blocked, which gates pending
  4. Read sw_core_changelog.md    → any pending propagation
  5. Read progress.md (last entry)→ what was done last session

Only AFTER all 5 → Master has valid state → present SR checkpoint to KN
```

### Coordination Flow

```
SESSION OPEN
  │
  ├─→ A-TRACK: Task("Generate family dashboard from state files")
  │     Returns: {products: [{id, phase, status, %_complete, next_gate}], flags: [...]}
  │
  ├─→ A-SCHEDULE: Task("Propose session allocation given hours_remaining and priorities")
  │     Returns: {recommendation: "Work on I-XX", reason: "...", alternatives: [...]}
  │
  ├─→ A-DEPEND: Task("Check dependency status for all blocked products")
  │     Returns: {I-02: {status: BLOCKED, missing: [...]}, I-08: {status: BLOCKED, missing: [...]}}
  │
  └─→ HITL: SR checkpoint → KN confirms or overrides product selection
        │
        ├─ If conflict detected → HITL: CA checkpoint → KN arbitrates
        │
        └─ Product selected → Dispatch to per-product Pattern 3 instance
             │
             ├─→ Task("Execute Phase {{N}} work on I-XX using Pattern 3 agents")
             │     Pattern 3 handles: phase agents, QC, per-product gates
             │
             └─→ On completion:
                   ├─→ A-SYNC: Task("Check for shared artifact changes")
                   │     If changes → HITL: AP checkpoint → KN approves propagation
                   │
                   ├─→ A-TRACK: Task("Update family_state.md with session results")
                   │
                   └─→ If Friday → HITL: WR checkpoint → KN approves next week allocation
```

### Cross-Product Gate Flow

```
Product I-02 requests Phase 1 start:
  │
  ├─→ A-DEPEND: Task("Verify DG-1: I-01.Phase3.ACCEPTED")
  │     Reads: I-01_state.md → checks phase3_gate field
  │     Reads: I-01 Phase 3 artifacts → checks for open CRITICAL flags
  │     Returns: {gate: "DG-1", evidence: [...], verdict: PASS/FAIL}
  │
  └─→ HITL: DG checkpoint → KN reviews evidence
        │
        ├─ APPROVE → I-02 status changes BLOCKED → ACTIVE in family_state.md
        ├─ BLOCK → I-02 remains BLOCKED, missing criteria listed
        └─ PARTIAL → I-02 starts Phase 0/1 only, Phase 2+ blocked
```

### Dependency Regression Detection

```
I-01 Phase 3 gate → REVISE (regression):
  │
  ├─→ A-DEPEND: Task("Check if any dependent product assumed I-01.Phase3.ACCEPTED")
  │     Returns: {affected: ["I-02"], status: "I-02 is at Phase 1, started after DG-1 APPROVE"}
  │
  └─→ HALT-3 triggered → Master immediately:
        ├─ Flags I-02 as PAUSED (dependency regression)
        ├─ Presents to KN: "I-01 Phase 3 regressed. I-02 Phase 1 work may be invalidated."
        └─ KN decides: continue I-02 (if Phase 1 unaffected) or halt and rework
```

## Section 4: Conditional Edges

### Coordination Layer Edges

| Step | Trigger | Edge | Action | After Max |
|------|---------|------|--------|-----------|
| **S1 Portfolio Intake** | Misread timeline | Retry (×2) | Re-read source doc | Escalate → KN |
| | Conflicting priorities | Escalate | Present tradeoff to KN | KN decides |
| **S2 Resource Allocation** | Sum > 22h allocatable | Retry (×1) | Re-propose, cut lowest priority | Escalate → KN cuts product |
| | Developer unavailable >2 weeks | Escalate | KN reviews hiring risk | — |
| | Persistent over-commitment | Escalate | A-SYSTEMS archetype analysis | — |
| **S3 Dependency Resolution** | Ambiguous state | Retry (×1) | Re-read with explicit criteria | Escalate → KN interprets |
| | Dependency not met | Reroute | Work on dependency product instead | — |
| | Dependency file missing | **Halt** | File must exist before proceeding | KN creates file |
| **S4 Phase Dispatch** | Wrong phase | Retry (×1) | Re-read progress file | Escalate → KN |
| | All products blocked | Escalate | KN decides: cross-cut work or wait | — |
| **S5 Artifact Sync** | Incomplete propagation | Retry (×1) | Regenerate from change log | Escalate → KN |
| | Breaking change downstream | Reroute | Flag BEFORE propagation | KN decides |
| | Safety-critical param change | **Halt** | All downstream products frozen | KN + QC gate |
| **S6 Conflict Detection** | False positive | Retry (×1) | Re-check allocation tracker | — |
| | Confirmed conflict | Reroute | → S7 Priority Arbitration | — |
| **S7 Priority Arbitration** | Resource conflict | Escalate (always) | AI presents tradeoff, KN decides | — |
| **S8 Cross-Product Gate** | Gate rejected | Reroute | Return to source product | — |
| | Dependency regressed | **Halt** (HALT-3) | Dependent product paused | KN reassesses |
| | Premature request | **Block** | A-DEPEND refuses, shows missing | — |
| **S9 Progress Tracking** | File read error | Retry (×2) | Re-read with path check | Escalate |
| | Slip >2 weeks | Escalate | KN decides: rebalance or accept | — |
| **S10 Rebalancing** | Violates 22h cap | Retry (×1) | Re-propose within constraint | Escalate → KN cuts scope |
| | No valid allocation | Escalate | KN freezes product or extends timeline | — |
| | >2 weeks over-commitment | **Halt** | A-SYSTEMS archetype (B3 Depletion) | — |

### Three Safety Halt Conditions (Absolute — No Override)

```
HALT-1: Dependency file missing or corrupt
        → No product advances without valid state file
        → Master cannot infer state from memory

HALT-2: Breaking change to safety-critical shared parameter
        → All downstream products frozen until QC + KN review
        → A-SYNC cannot propagate without explicit approval

HALT-3: Dependency product regressed after dependent product started
        → Dependent product immediately paused
        → Cannot continue building on invalidated foundation
```

### Edge Design Principle

Pattern 4 edges are primarily ESCALATE and HALT, not RETRY. Coordination errors are structural (wrong priority, missing dependency, resource conflict) and require human judgment, not a second attempt at the same logic.

| Pattern | Primary Edge | Why |
|---------|-------------|-----|
| 1 (Pipeline) | Retry → Escalate | Transient errors in sequential steps |
| 2 (State Machine) | None → Manual mode | Real-time, no retry budget |
| 3 (Workflow) | Reroute → Pause | Phase-level rework |
| **4 (Parallel Pipeline)** | **Escalate → Halt** | **Coordination errors are structural** |

### SR — Session Routing

```yaml
id: "SR-{{session_number}}"
trigger: "Session open, after 5-file read protocol"

  - "Recommendation: 'Work on I-XX because {{reason}}'"

  - "Hours remaining: {{N}} of 22h"

  confirm: "Work on recommended product"
  override: "Work on different product (state reason)"
  cross_cut: "No product work — QC / D-M-I-R / B-NS"

```

### CA — Conflict Arbitration

```yaml
id: "CA-{{product_A}}-{{product_B}}-{{resource}}"
trigger: "A-SCHEDULE detects two products need same resource"
info_package:
  - "Products: I-XX vs I-YY"
  - "Resource: developer / fab shop / KN time"
  - "Impact A: I-XX advances, I-YY slips {{N}} days"
  - "Impact B: I-YY advances, I-XX slips {{N}} days"
decision_format:
  A: "Prioritize I-XX"
  B: "Prioritize I-YY"
  C: "Split resource (if divisible)"
  D: "Defer both"
```

## Section 6: Loop Prevention Rules

### Rule 1: No Circular Dependencies

```
The dependency map is a DAG (directed acyclic graph).
  I-09 → independent
  I-01 → independent
  I-02 → depends on I-01
  I-08 → depends on I-01 AND IRONMESH

No product can depend on a product that depends on it.
If a circular dependency is ever detected → HALT → architecture is wrong.
```

### Rule 2: No Infinite Rescheduling

```
A-SCHEDULE proposes allocation.
If KN rejects → A-SCHEDULE re-proposes ONCE with different parameters.
If rejected again → KN writes allocation manually.
A-SCHEDULE never proposes more than 2× per session.
```

### Rule 3: No Dependency Gate Re-Litigation

```
Once DG-1 is APPROVED, I-02 is unblocked permanently (unless HALT-3 triggered).
A-DEPEND does not re-check passed gates every session.
Only HALT-3 (dependency regression) can re-block an approved product.
```

### Rule 4: No Propagation Loops

```
A-SYNC propagates changes downstream only (I-01 → I-09/I-02/I-08).
Downstream products NEVER propagate changes upstream to I-01.
If a downstream product needs a SW core change → file a change request on I-01.
I-01 is always the canonical reference for shared software.
```

### Rule 5: No Phantom Work

```
Master only dispatches work to ACTIVE products (not BLOCKED).
A-TRACK verifies product status before any Task() delegation.
If product is BLOCKED → Master cannot "start early" or "do preliminary work."
Exception: DG with PARTIAL decision allows Phase 0/1 only.
```

1. **Meta-pattern architecture** — coordinates Pattern 3 instances, doesn't replace them
2. **Dependency gates (DG)** — cross-product gates with evidence checklists

4. **Artifact propagation control** — A-SYNC agent prevents silent divergence
